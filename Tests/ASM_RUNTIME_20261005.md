# Перенос runtime на ARM Thumb-2, 05.10.2026

База: 3450335, codex/comm-core. Плата, COM, прошивка, сервер, SMS и реле не использовались.

## Этап A: ранее переделанная исполняемая логика

В IAR-проекте семь C translation units заменены самостоятельными ASM-модулями:
`user_fun`, `flash_w25`, `memory`, `photo`, `crc`, `idindex`, `user_comm`.
Перенесены целые модули, чтобы не оставлять C-условия вокруг ASM-ядер.
Полный список 309 функций — `asm/runtime_inventory.json` (по модулю).
Он включает server_rx_* (бюджет, CRC, reset, владение входом), w25_async_*,
mem_config_* и cfg_* (публикация/очистка/ошибки), store_* и user_storage_*,
log_async_*/log_storage_poll, fw_async_*/fw_storage_poll, crc16_append_ff,
ID-поиск/счётчики/хеш-обвязки, фото и вызывающие функции user_comm.

ASM получен из установленного IAR 9.50.1, проверен повторным ассемблированием
и хранится в репозитории. Обычная сборка **не компилирует C-эталоны** и не
генерирует ASM автоматически. Условия, циклы, ожидание, отмена и ошибки находятся
в `.s`. `Tests/asm/port_runtime.py` — явный инструмент воспроизведения переноса.
Устранена несовместимость listing с assembler: CFI FunCall вынесен перед IT;
инструкции IT-блоков сохранены. AAPCS/PRESERVE8/REQUIRE8 и CFI сохранены.

C-эталоны находятся только в `Tests/asm/reference/User`. В production C остались
объявления отладочных типов `User/runtime_layout.c` (36 байт readonly data)
и не затронутые этим переносом модули периферии/связи/загрузчика. В main и USB
прежние связующие вызовы сохранены. `User/sector_journal.c` пока общий неизменённый
startup/recovery и синхронный API; runtime таблиц заменяется следующим этапом.
Этот этап не объявляет таблицы или фотографии пошаговыми.

## Этап B: таблицы и секторный журнал

Команды 13/14/15/16 выполняют проверку длины и приобретают собственную копию
записей (до 2016 байт для сетевого кадра). Дальше их продвигает
`user_storage_poll`, без новых входящих данных. Старые `sync_write_cells`,
`mem_replace_pages`, `sj_replace_pages`, `holiday_write` остаются независимым
синхронным эталоном/служебным API; runtime команд больше их не вызывает.

Новые ASM-функции: table_runtime_active/blocks_reads/quiet/cancel/begin/poll/finish,
table_chunk, table_scan_begin, sj_runtime_begin/poll/cancel/reset/blocked,
sjr_start/fail, idindex_runtime_suspend. Изменены ASM вызывающие функции
user_parse_comand, user_storage_poll/command_ready/flash_ready, user_savereset,
store_usb_session, user_comm_session, mem_tables_ready. Резервная копия → CRC →
28 байт metadata → 4 байта commit → erase назначения → copy → CRC и побайтовое
сравнение → erase metadata. Формат SJ версии 1 и loader recovery не менялись.
Одинаковый сектор не стирается повторно. Для пакета, возвращающегося к прежнему
сектору, сохранён прежний порядок последовательных секторных транзакций.

Один шаг: callback/чтение/CRC 64 байта, максимум 128 прочитанных байт либо один
async start/poll. Callback рассматривает не более числа записей кадра (63 для
ID). Курсор группы меняется после verified; timestamp/CRC-ответ — после всей
операции. Отмена до commit оставляет назначение прежним; после commit завершает
текущий сектор и не начинает следующий. Reconnect/USB reset подавляют старый ACK.
Ожидание выходного слота ограничено 2 с. После неопределённого commit доступ к
таблицам закрыт до startup recovery, без синхронного recovery из runtime.

Индекс ID временно выключается, после проверки базы получает новые count/hash/end;
его прежнее фоновое восстановление сохранено. CRC всей ID-базы теперь требует
конечного полного прохода по 64 байта: это увеличивает общую работу и время
владения Flash, но ограничивает отдельный шаг. Другие владельцы Flash ждут;
главный цикл продолжает связь/таймеры. Программный reset отменяет таблицу и ждёт
освобождения NOR. Физический BUSY ограничивается прежними таймаутами W25, а не
циклом ожидания в автомате. Suspend/resume не используется.
