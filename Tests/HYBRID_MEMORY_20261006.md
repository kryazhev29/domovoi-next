# HYBRID_MEMORY_20261006 — результат этапов B–E

База `51e207a`, логика исходной базы `d9e3dd5`. Работа локальная, без устройства и сервера, без коммитов по поручению владельца. План принят ранее: [таблица функций и исходные оценки](../docs/hybrid_memory_plan.md).

HYBRID: **BIN 88765 Б**, свободный промежуток ОЗУ **2184 Б**. Цель BIN ≤87633 не достигнута на **1132 Б**, ОЗУ ≥3072 — на **888 Б**. Функции не урезались. От исходного C BIN меньше на 2964 Б, от ASM — на 3952 Б; запас ОЗУ вырос на 2120 Б.

## Проверки и воспроизводимость

- IAR EWARM 9.50.1.380, Release High/Size: ASM/C/HYBRID — 0 ошибок. Stack analysis включён; Ls014/Ls016 остаются по причине ниже.
- `run_all --project ASM|C|HYBRID`: **71/71 для каждого**, включая мутации и обрывы питания. Перед изменениями свежие C/ASM: 67/67; первичный HYBRID: 67/67.
- Парное сравнение ASM/C/HYBRID: **198 сценариев, 0 расхождений**. Сохранённые `result`/`returned` исходного ASM также совпали во всех 198 сценариях всех вариантов; новый код не сравнивался только с самим собой.
- Горячие полные пути карта → GPIO и сервер → commit проверены отдельно; таблицы ниже. Это инструкции Unicorn, не DWT и не проверка платы.
- Владение: 196 упорядоченных пар, 50 допустимых; запрещённые пары получают отказ без изменения данных. Реальные FW/config handoff, photo/upload ACK/retry/cancel и 25 одиночных IRQ-вставок проверены.
- Форматирование: 2097152 STATUS случаев, все сетевые значения/сигнал/флаги, все ushort firmware × флаги; границы u32/i32/hex и 100000 дополнительных значений, NUL и canary. Linked ELF проверяет ABI STATUS с семью аргументами в стеке и scalar boundaries. `__iar_small_memcmp`: 704 комбинации длины/выравнивания/различий и NULL при n=0.
- USB: 420 комбинаций границ/PRIMASK/reset, атомарность публикации и backpressure; максимальный ответ 1038 Б не публикуется при свободных 1037, принимается после освобождения 1038.

Python — `%TEMP%/codex-py311/python.exe`, зависимости — `%TEMP%/codex-deps`, Zig — `DOMOVOI_ZIG`, оба Zig cache перенесены в TEMP. IarBuild `-build` не проходит sandbox canonicalization; `Tests/build_iar.py` выполняет реальные команды IarBuild `-jsondb`, включая assembler/compiler/linker/ielftool. Это успешная сборка IAR-инструментами, не утверждение об успешном wrapper `-build`.

Последняя правка CFI/пробелов меняет метаданные ELF; три проекта пересобраны, BIN SHA-256 побайтно прежние. Связь финальных BIN с образами полного прогона записана в JSON; свежий ELF HYBRID дополнительно прошёл workspace/access/formatter. Независимые полные три-проектные прогоны после каждого промежуточного C/D подшага не заявляются: полный набор выполнен для окончательной совокупности изменений.

Это необходимо для реального ACK при сохраняемом photo-context, а не только синтетического acquire. FW отдаёт reserve перед CONFIG, сохраняя context. NOR/wire сравниваются с исходным образом.

## Стек и USB

IAR без полного графа: основная цепь ASM/HYBRID 2376 Б, C 2216 Б; максимальная IRQ-цепь 144, сумма IRQ roots 256 во всех трёх. `(2376+256)*1.25`, округлённое к 8, равно 3296 Б (аналог C 3096), но использовать это как доказанный размер нельзя: косвенные вызовы и все допустимые вложения IRQ не закрыты. `settings/runtime_stack.suc` — отключённый кандидат из 48 callback связей, полнота не сертифицирована. Две квалифицированные попытки линковки (включая recursion depth) закончились внутренним AccessViolation 0xc0000005, чтение 0x8; третьей попытки не было. Поэтому Ls014 (ASM/HYBRID) и Ls016 (все три) объяснены, не скрыты.

## E1. Загрузчики: расчёт без правок

| Артефакт | Код, Б | RO data, Б | Полезный RO, Б | BIN, Б |

C-оболочка оставляет тот же переход без старого тела. `user_comm_boot` удержан ASM: горячий `store_config_complete` входит в его общий внутренний хвост. `fw_log` также удержан: из `fw_update_quiet` существует короткая внутренняя ветка. Принудительное отделение таких входов потребовало бы изменения горячих инструкций, поэтому сравнивались замкнутые группы. CRC16, журнал, server/user_comm RX, config/status/snapshot и карточная группа C сохранены. Горячие либо общие с горячими storage/parser helpers не объявлялись независимыми холодными функциями.

Повторный проход девяти модулей не нашёл дополнительного уменьшения. Последние пять подстановок photo/fw_service/upload/idindex/sector_runtime дали +40/+40/+24/+88/+8 Б к выбранному BIN: пять шагов без выигрыша, после них поиск микровыигрышей остановлен по условию задания. Все альтернативы остались только в TEMP. Существенного оставшегося выигрыша для покрытия 1660 Б эти измерения не показывают; достижение лимита BIN не заявляется.

### USB TX: источник, PMA и владение

Кольцо `USART_Rx_Buffer[1040]` и три счётчика заменены одним дескриптором: источник 4 Б, длина 2 Б, смещение 2 Б; прежняя эпоха сохранена. RW data уменьшилось на **1044 Б**. После выравнивания CSTACK свободный промежуток вырос на **1048 Б**: `CSTACK 0x20003320…0x20004320`, `fault_record 0x20004FC0`. Это статический промежуток карты, а не измеренный остаток динамического стека. Heap/allocator отсутствуют, workspace остаётся 2224 Б; pin/deferred-release помещены в прежние резервные четыре байта.

Публикация производится при сохранённом PRIMASK: все проверки, захват владельца и при необходимости копирование завершаются до публикации указателя с DMB. Отказ не оставляет части пакета. Continuation из USB IRQ копирует из источника в PMA порциями до 64 Б; реальные вызовы — SOF и EP1 callbacks одного USB обработчика. После последней порции источник удерживается **до последнего IN ACK**; PMA callback не освобождает рабочую область. Main собирает завершённое владение при конфликтном захвате области, освобождении прикреплённого владельца либо следующей публикации USB. Reset снимает дескриптор и меняет эпоху; PRIMASK восстанавливается в исходное значение, старый производитель/continuation не дописывает новый сеанс.

WORK_REPLY, WORK_PHOTO_PACKET, WORK_UPLOAD_PACKET, WORK_SERVICE и WORK_IDCLEAR передаются прямо из памяти владельца, без копирования пакета. `work_release` активного USB-источника возвращает 0, откладывает освобождение и запрещает повторный захват той же области. Адрес уже освобождённой рабочей области отклоняется при публикации. Для стека/временного источника и изменяемого FW-контекста сохраняется снимок в **существующей** WORK_REPLY либо WORK_PHOTO_PACKET; отдельный TX-массив не добавлен. FW context нельзя одалживать: режим 16 повторно использует его до завершения USB, что выявилось на проверке реальных ответов.

Допускается один опубликованный пакет. Следующая неблокирующая отправка получает backpressure и повторяется после окончания первой; порядок ответов сохранён. Вместимость и число одновременно принимаемых мелких ответов старого кольца не воспроизводятся: новая граница приёма — свободный дескриптор **и** совместимый владелец. Нулевая отправка остаётся успешной без публикации. Предельный пакет 1039 Б и отказ для 1040 Б сохранены.

Linked-тесты исполняют реальных производителей, reset и IRQ continuation, моделируя только периферийную PMA/endpoint границу. Проверены длины 0/1/63/64/65/523/534/1014/1038/1039/1040/65535 при PRIMASK 0/1, порча прежнего стекового источника, прямые loan-адреса, раннее освобождение до/после публикации, блокировка повторного захвата, busy/retry/порядок, reset после шести вариантов числа порций и на **344 границах инструкций** приёма. Полные реальные ответы CRC/list/upload/clear/photo/FW (21/211/1038/11/534/19 Б) сохраняются до последнего ACK. Это проверки модели, не физического USB.

Промежуточный вариант безусловно проверял USB pin при каждом `work_acquire/release`: короткие CRC-входы получили 294 вместо 288 инструкций (+2,08%), что нарушало предел 1%. Проверка завершения перенесена на конфликтную ветку захвата и release прикреплённого владельца. Обычный успешный захват не платит за USB bookkeeping; короткие CRC-входы снова имеют 288 инструкций. Добавка 20 Б сохранена как необходимое восстановление ограничения скорости; владение и отказ раннего release проверены повторно после этой правки.

`tempStrBuffer[128]` оставлен. Даже с выключенным DEBUG_USER в Release он используется не только SMS STATUS: UCS2/SMS parsing, PIN/ID операции, временное имя ID и alias для CRC32/checkFirmware. Условие переноса из задания не выполняется; неподтверждённая экономия 128 Б не засчитана.

### Стек: воспроизводимый сбой и дешёвая защита

`Tests/probe_stack.py` воспроизводит AccessViolation IAR (чтение 0x8, exit 3) на текущих объектах с минимальным набором **трёх** правил:

```text
possible calls channel_emit [comm_channel.o]: server_channel_event [comm_server.o];
possible calls server_link [comm_server.o]: user_comm_link;
possible calls server_channel_event [comm_server.o]: user_comm_session, comm_recover_no_internet;
```

Перед падением Ls028 сообщает недостоверный recursion bound: `server_channel_event` рассчитан как 72 Б, хотя его вызов `server_link` имеет 1280 Б. Установка `max recursion depth … 2` не устранила падение. Отдельный маленький C-пример воспроизвёл предупреждение Ls028, **но не AccessViolation**; минимальный воспроизводитель падения использует реальные firmware objects, это не самостоятельный C-тест.

48 callback-правил подключены в Release. `exclude server_channel_event [comm_server.o];` обходится без внутреннего сбоя и Ls016; для HYBRID добавлен свой `.suc` с актуальными именами объектов/внешних helpers. Это разрыв проблемного цикла, **не полный доказанный граф**. Остаются Ls014 для ASM leaves и Ls015 для uncalled roots. Частичная карта HYBRID показывает entry 2320 Б, IRQ max/total 168/280 Б; эти значения нельзя использовать как доказанный worst-case для уменьшения стека.

Группировки NVIC в board/UART/USB 0/1/2 не менялись. Полного worst-case вложения IRQ и ручной оценки исключённого цикла нет, поэтому CSTACK **4096 Б сохранён**. Правило размещения не изменено; перенос в начало RAM не выполнялся.

В начале каждой итерации main проверяется слово STACK_PAINT `0x5A5AA5A5` на дне CSTACK. Проверка и путь отказа stackless. При порче IRQ запрещаются, 48-Б `fault_record` очищается, записываются reason `0x5354414B`, LR/MSP, frame_valid=0, затем после DSB последним публикуется прежний magic FLT1. Выполняется остановка без watchdog reload — тот же путь ожидания IWDG, что у существующего fault handler. Новый формат протокола/записи не вводится.

Цена canary — **80 Б BIN, 0 Б дополнительной RAM**, здоровая проверка **6 инструкций** плюс одна инструкция BL в main. Оценка прежней fetch-модели для самой проверки — **14 условных тактов**, это не такты Cortex-M3/DWT. Три значения порчи проверены на linked ELF: нет обращения к стеку, записи только в fault_record, PRIMASK=1, неизменный SP и терминальный цикл. Реальное время watchdog reset не измерялось. Canary обнаруживает затронутое нижнее слово при достижении main; управляемый отказ для произвольного переполнения до этой точки не доказан.
