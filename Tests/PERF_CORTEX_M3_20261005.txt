Что измерено

Реальные инструкции IAR в Unicorn, а НЕ такты, миллисекунды или задержка
всего устройства. Release: размерная оптимизация -Ohz. Для отдельных ядер
также собраны C -Ohs и C с развёрнутым циклом. Для фото и резервного поиска
заменены только mem_read и обслуживание watchdog/индекса: время SPI/Flash
не входит. Число и объём чтений старой и новой версии совпадают.

Отношение — прежнее число инструкций / новое. Это не общий множитель
скорости прошивки. У обычного корректного кадра 20 байт сканирование
242 -> 237 инструкций; у неполного заголовка 5 байт 61 -> 66. Большой
выигрыш сборщика относится к повторному поиску после повреждённого кадра.
Он копировал 2096128 байт внутри буфера 2048 байт; теперь — ноль, либо
только сохранившийся хвост (3 байта для SLD). Это исправление алгоритма C.
У специально сформированного буфера из 340 правдоподобных вложенных
заголовков каждый кадр заканчивается в последнем байте и имеет плохой CRC.
Здесь выигрыш 3,95 раза: повторный расчёт CRC всё ещё требует 3,57 млн
инструкций. Это оставшееся слабое место бюджета одного прохода. Для строгого
лимита нужны отдельное поэтапное сканирование/CRC и сохранение состояния;
такое изменение контракта обработчика в эту серию не входит.

Хеш: C -Ohz 135, C -Ohs 56, развёрнутый C -Ohz 49, развёрнутый C -Ohs 41,
ASM 40 инструкций. Основная часть выигрыша — разворачивание цикла.
ASM даёт фиксированные чтения ровно 10 байт и не использует стек;
прежний связанный C использовал 16 байт. FNV-1a, порядок двух байт индекса
и результат сохранены, поэтому формат индекса и контрольные суммы прежние.

CRC хвоста: исключены промежуточная матрица результата и ненужное последнее
возведение в квадрат. Для длины 0 функция сразу возвращает исходный CRC.
Максимальное уменьшение SP в модели: 144 -> 104 байта. Это локальный стек
функции с вызовами, а не уменьшение зарезервированной RAM приложения.

Почему остальные участки оставлены

Проверка FF в буфере 256 байт: C по одному байту 1798 / 1540 инструкций
(-Ohz / -Ohs), группировка по четыре байта без нарушения выравнивания
907 / 718. Но при первом грязном байте соответственно 9 / 8 против 16 / 21.
Это следующий кандидат для профилирования на плате: нужен состав реальных
страниц и доля CPU во времени чтения. ASM пока не добавлен; сейчас также
идёт отдельная переделка владения Flash и ожидания её готовности.

Сравнение равных ID длиной 10: настоящая IAR __iar_small_memcmp — 69
инструкций; обычный цикл C — 75 / 68. Переписывание такого цикла на C не
даёт полезного выигрыша. Специализированное ASM-сравнение потребует замера
разных позиций несовпадения; замена всей библиотечной memcmp не обоснована.

crc8_calc не имеет вызовов в User/Modules и отсутствует в итоговом map.
Её перевод на ASM не ускорит текущую прошивку. ix_bucket ещё вызывает C
ix_fnv; его отдельный фиксированный 10-байтовый хеш и gf2_apply — кандидаты
следующего прохода, без заявленного аппаратного выигрыша.

ISR, автоматы связи, драйверы и операции копирования целиком не переводились.
Подтверждённая большая потеря на memmove устранена на уровне алгоритма.
Блокирующее стирание Flash и SLA поиска 50 мс при повреждённом индексе этим
проходом не решены: объём чтений резервного поиска остался прежним.
