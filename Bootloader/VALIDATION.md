# Проверки 14 сентября 2026

- ARM GCC 12.3: сборка и линковка v5, MINI, MODEM выполнены. Версия 0x31,
  каждый BIN 32768 байт, ID по 0x08007FFC. Адреса приложения сохранены.
- C-модель: 206 точек полного/частичного сбоя установки и 260 точек отката/очистки;
  неверные CRC, HW нового формата, размеры, векторы, пустая Flash, повтор
  восстановления, максимальный образ. Старый заголовок с недостоверным HW принят.
  Отказ записи резервной копии: приложение сохранено, запрос снят, код 3 в журнале,
  повторный старт не трогает Flash. Проверка падает на предыдущей версии boot_core.c.
- Оборванное стирание журнала перед следующим обновлением: исправное приложение
  не заменяется старой копией. Проверка падала до исправления.
- Пробный запуск (версия 0x32): 3 запуска и откат, подтверждение, недописанное
  подтверждение, запрос отката из FW, образ без метки, установка без копии,
  повреждённая копия. 302 точки сбоя питания цепочки «установка — 3 запуска —
  откат» и 300 точек с запросом отката, полная и частичная запись. Каждая точка
  заканчивается на прежней версии с завершённым пробным запуском, без режима
  восстановления. Восемь намеренных поломок boot_core.c (лишний запуск, порядок
  записи, неучтённый первый запуск, игнор запроса, недописанное подтверждение,
  снятая защита журнала, откат с повреждённой копией, негашёный бит) ловятся тестами.
- USB загрузчика: разбиения BEGIN, неверные CRC/длина, переполнение, шум, повтор
  блока, смещение, преждевременный COMMIT, неподдерживаемый объём Flash.
- Ручной протокол: запрет не-USB канала, размер, объём Flash, неполный образ,
  повторы блоков, отмена, ошибочный HW файла, CRC и повреждение перед записью;
  129 позиций сброса при передаче, включая принятый COMMIT. Автозапуска записи нет.
- Python: 4 теста CRC, старой упаковки, адреса приложения и вспомогательного embed.
- Unicorn: 12 проверок ARM-кода GPIO/защиты Flash для трёх профилей и значений
  заводского регистра 128, 64, 0, FFFF КиБ.
- Изолированная SRAM-секция нового writer выполнена в Unicorn: полный образ,
  повреждение SPI на страницах 0/7, пять прерываний. Все исполняемые инструкции
  находились в SRAM; приложение от 0x08008000 осталось неизменным во всех случаях.
- app_update.c и boot_manual.c скомпилированы ARM GCC через временную совместимость
  с IAR intrinsics. user_fun.c прошёл syntax-only после адаптации анонимного
  глобального union IAR во временной копии. Это не полная сборка приложения IAR.
- GUI: 11 тестов модели транспорта/интерфейса пройдены. EXE пересобран после
  исправления устаревшей инструкции о встроенном загрузчике.

Правки того же дня (запуск целого приложения при сбое внешней Flash, разовая
отправка кода ошибки, диапазон числа блоков в команде 19) прошли все проверки
выше, кроме GUI: утилита не менялась. Запуск приложения из main() на хосте
не моделируется: boot_start_app() сам проверяет CRC и векторы.

Приложение с пробным запуском собрано в IAR Release без ошибок: 60 869 байт,
метка пробного запуска в образе есть. Код приложения для пробного запуска
(`app_update.c`, `user_fun.c`, `user_gsm.c`) проверен только сборкой.
BIN загрузчика 0x32 ещё не пересобраны: описанные выше BIN — версия 0x31.
Следует проверить размещение __ramfunc и стек по итоговой IAR map перед испытаниями.
NextConfig ещё не реализует команду 110. Реальные платы с загрузчиком 0x32, USB,
SPI, питание и сервер не проверялись. Потеря питания при записи самого загрузчика
может потребовать SWD.

В GCC остаются предупреждения исходного USB SDK о pragma/comment и bare-metal
main. Модели не подтверждают пригодность для массового обновления.
