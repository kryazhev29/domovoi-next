# Domovoi Service 1.0.0

Оконная утилита для Windows x64. Готовый DomovoiService.exe запускается без
установки Python. Для устройства нужен работающий драйвер USB CDC.
Обновление идёт по USB, не через сервер и не по мобильной связи.

## Порядок работы

1. Подключить USB и войти в загрузчик, удерживая BOOT при включении питания.
2. Нажать «Найти контроллер». Это запросы идентификации ко всем перечисленным
   COM-портам. Если подключено другое оборудование, выбрать порт вручную и
   нажать «Проверить выбранный», чтобы опрашивать только его.
3. Выбрать открытый BIN приложения с именем HW.FW.TIMESTAMP.bin.
   Окно покажет HW, FW, дату UTC, размер, вычисленный CRC и адрес приложения.
4. Нажать «Обновить контроллер». Кнопка доступна только после определения
   совместимого контроллера с загрузчиком от 0x31 и проверки файла.
5. Дождаться результата. «Образ принят» подтверждает приём загрузчиком,
   но НЕ завершение установки или успешный запуск. Версию приложения нужно
   проверить на сервере после восстановления связи.

Остановка допускается до отправки запроса установки. Потерянные подтверждения
блоков вызывают до двух повторов того же блока. BEGIN и COMMIT автоматически
не повторяются. После отключения кабеля продолжения с сохранённого места нет:
нужно снова войти в загрузчик и начать загрузку заново. При потере ответа на
COMMIT установка могла начаться — сначала выяснить фактическое состояние платы.

Утилита не снимает защиту чтения, не записывает загрузчик через SWD и не
запускает массовые обновления. При старте выполняется только перечисление портов,
без их открытия. Настоящие обращения начинаются по нажатию пользователя.

## Журнал и подготовка пакетов

Журнал автоматически пишется в `%LOCALAPPDATA%\DomovoiService\logs`.
Кнопка «Сохранить журнал» сохраняет копию в выбранный файл. Записываются путь
образа, метаданные, этапы и ошибки; содержимое прошивки в журнал не попадает.

Во вкладке «Для разработчика» можно создать пакет `.legacy` для старого
загрузчика. Это упаковка выбранного приложения, не создание переходной прошивки.
Исходный BIN защищён от перезаписи тем же путём. Версия FW старого пакета ≤255.
Команда CLI `boot_tool.py embed` сохранена для встраивания загрузчика в C-код.

## Сборка и проверка

Python 3.11 x64 с Tkinter. Создать отдельное venv и установить `pyserial==3.5`
и `pyinstaller==6.16.0`, затем выполнить `build_desktop.ps1 -Python <venv-python>`.
Упаковка следует документации https://pyinstaller.org/en/stable/usage.html.

Тесты: `python -m unittest discover -s tests -p "test_desktop*.py" -v`,
затем существующие `test_tool.py`. UI-тесты требуют Windows с Tkinter.
Тесты используют модель COM-порта и синтетические образы; устройства не открывают.
`DomovoiService.exe --demo --smoke-test` проверяет запуск EXE без обращения к портам.
`--demo` блокирует реальные операции с устройством.

Проверены фрагментация, шум, CRC ответа, запоздалое подтверждение, повтор блока,
отмена до COMMIT, несовместимый HW/старый загрузчик, изменение файла после проверки,
потеря ответа на установку, блокировки интерфейса и упаковка старого формата.
Реальная передача по USB и обновление физической платы этой утилитой не проверены.
Текущий протокол не позволяет автоматически подтвердить запуск новой прошивки.
