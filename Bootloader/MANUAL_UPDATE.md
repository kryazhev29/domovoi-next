# Ручная замена загрузчика через сервисное ПО

Сервер обновляет только рабочую FW командами 19/20. Замена загрузчика доступна
в работающей FW только по USB через новую сервисную команду 110. Штатный
NextConfig пока не реализует эту команду: описанный ниже клиент нужно добавить.
Внутренняя утилита Domovoi Service её также не отправляет.

Замена выполняется один раз при переводе изделия из старой системы в новую.
После перехода штатно обновляется только FW. Серверных команд и запросов
обновления загрузчика в исходной системе нет; они не добавляются.

## Переход установленных изделий

1. Старым конфигуратором через старый загрузчик установить новую рабочую FW,
   упакованную в совместимый старый формат. Адреса приложения не меняются.
2. Запустить эту FW и подключить новое сервисное ПО по USB.
3. Пользователь выбирает фотографию своей платы и соответствующий отдельный
   файл загрузчика. ПО показывает выбор и запускает замену по явной команде.
4. Передать файл, подтвердить запись, дождаться перезапуска и повторно прочитать
   версию загрузчика и HW. Ответ на COMMIT означает только принятие запроса.

Загрузчик не встроен в приложение. Сборку приложения с загрузчиком можно делать
отдельно для заводского программирования, но она не является файлом обновления FW.
Старый HW не позволяет определить плату. До нового загрузчика приложение сообщает
HW=0. После замены оно читает ID нового загрузчика. Поддерживается только v5 HW139;
перед заменой плату необходимо сверить по фотографии.

## Команда 110

Используется существующая оболочка сервисного протокола и её uniqId. Ниже описана
только полезная нагрузка после байта команды. Все многобайтные числа little-endian.

| Операция | Полезная нагрузка | Назначение |
| --- | --- | --- |
| BEGIN | `00 size:u32 crc:u32 hw:u8` | Стереть область приёма и начать сеанс |
| DATA | `01 offset:u32 data:1..256` | Передать следующий блок |
| COMMIT | `02` | Проверить весь образ и явно запустить замену |
| CANCEL | `03` | Отменить сеанс до COMMIT |
| STATUS | `04` | Прочитать состояние текущего сеанса |

`size` строго 32768. Передаётся открытый BIN загрузчика целиком, без заголовка FW
и без старого шифрования. `hw` равен 139 для v5.
Последние четыре байта образа: `32 8B 00 FF`. CRC считается по всем 32768 байтам:
STM32 CRC32, полином 0x04C11DB7, начальное значение 0xFFFFFFFF, слова little-endian,
без отражения бит и финального XOR. Эталон вычисления — `boot_tool.py:crc32`.

Ответ команды 110 содержит 8 байт: `op:u8 status:u8 received:u32 hw:u8 armed:u8`.
Статусы: 0 — принят, 1 — неверные параметры/образ/порядок, 2 — ошибка памяти,
3 — занято, 4 — запрещено, 5 — неверный CRC. Проверка канала в общей диспетчеризации
может вернуть штатный CMD_PARAMERROR; обновление FW — CMD_RUNNING.

Клиент ждёт ответ на каждый блок и проверяет `received`. Разрешён точный повтор уже
принятого блока. Пропуски, выход за размер и повтор с изменёнными байтами отклоняются.
После потери связи следует проверить STATUS; после перезапуска нужен новый BEGIN.
BEGIN начинает сеанс заново, а не продолжает прежнюю передачу.

После успешного COMMIT приложение отправляет ответ, выдерживает 200 мс и запускает
запись из RAM. При сбое предварительной проверки возможен второй ответ с ошибкой.
Нельзя считать тайм-аут после COMMIT ни успехом, ни разрешением автоматически
повторить замену: дождаться устройства и проверить его метаданные. Отмена после
COMMIT запрещена. Серверный канал отвергается до записи во внешнюю Flash.
При ручном сеансе команды FW 19/20 блокируются; при обновлении FW команда 110 занята.

## Память и ограничения

Приём использует первые 32 КиБ области кандидата внешней Flash. Проверяются размер,
CRC, векторы и ID. Перед стиранием каждой внутренней страницы её данные повторно
читаются из SPI и сверяются с заранее рассчитанным CRC. Запись затрагивает только
0x08000000–0x08007FFF. Заголовок приложения остаётся по 0x08008000, векторы по
0x08008200. Старый формат заголовка приложения допускается без доверия к его HW;
новый формат сохраняет строгую проверку HW.

Разрешение записи существует только в RAM. Сброс до начала записи не запускает
замену автоматически. Отключение питания во время перезаписи самого загрузчика
может потребовать восстановления через SWD; откат приложения это не устраняет.

Аппаратный адаптер рабочей FW использует SPI1 и CS из board.h для v5.
Команды сборки и проверок приведены в ../AGENTS.md; результаты — в ../docs/history/.
