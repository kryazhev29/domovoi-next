# Загрузчик Domovoi Next

Реализация для STM32F103CB с неизменным адресом приложения `0x08008200`.
Версия загрузчика — `0x31`. Старые исходники сохранены без изменений.

## Сборка

IAR: откройте `DomovoiBoot.ewp`. Конфигурации `Debug` и `Release` — v5,
`Mini_Release` — старый MINI, `Modem_Release` — старый MODEM.
Сборка в IAR ещё не выполнялась; поставляемые BIN собраны ARM GCC (ниже).

Независимая сборка: `python build_gcc.py <путь-к-arm-none-eabi-gcc.exe> v5`.
Последний аргумент: `v5`, `mini` или `modem`. Скрипт не подключается к плате.
Результат — `build/gcc-<профиль>/DomovoiBoot.bin` и ELF/MAP.
Бинарник ровно 32768 байт; свободная область заполнена FF. Линковщики
ограничивают код адресом `0x08007FFB`, следующие четыре байта — идентификаторы.

## Память и формат

| Область | Адрес | Размер |
|---|---|---|
| Загрузчик во внутренней Flash | 0x08000000 | 32 КиБ |
| Заголовок приложения | 0x08008000 | 512 байт |
| Векторы и код приложения | 0x08008200 | до 97792 байт |
| Новый образ во внешней Flash | 0x00000 | 128 КиБ |
| Журнал обновления | 0x20000 | 4 КиБ |
| Резервная копия | 0x21000 | 128 КиБ |

Разделы внешней Flash совпадают с `MB_FIRMWARE`/`MB_BACKUP` приложения;
журнал занимает существующий промежуток между ними. Он не пересекается с базой
идентификаторов, которая начинается с `0x41000`.

`BootHeader` совпадает с 32-байтным `bootFWparam_s`. Новый magic — `0x4E465744`.
Для запуска и резервирования также принимается старый `0x57464C53`.
CRC — STM32 CRC32, полином `0x04C11DB7`, начальное значение `0xFFFFFFFF`,
по 32-битным little-endian словам, без финального XOR. Образ выровнен до 4 байт.
Проверяются границы размера, аппаратный ID, стек, Thumb-бит и адрес Reset_Handler.

## Обновление и откат

1. Полностью загрузить и проверить новый образ во внешней Flash.
2. Опубликовать запрос; до этого magic заголовка оставлен FF.
3. Скопировать действующее приложение вместе с заголовком в резервный раздел
   и проверить его CRC. Только затем записать начало транзакции в журнал.
4. Стереть и записать приложение; заголовок записывается последним.
5. Проверить установленный образ и завершить транзакцию. При ошибке записи
   восстановить проверенную резервную копию и сохранить код ошибки.

После сбоя питания незаконченная установка повторяется либо продолжается откат.
Состояние журнала учитывает частично записанные маркеры. Повреждённое приложение
не запускается. Аппаратный вход удерживает устройство в USB-загрузчике до успешной
установки. Это откат при ошибке установки/CRC, а не проверка работоспособности
бизнес-логики после запуска: подтверждения жизнеспособности приложения нет.

При успешной установке снимается запрос обновления (magic кандидата обнуляется).
После отката область кандидата очищается. Эти пути завершения различаются.

Если резервную копию записать не удалось, установка не начинается: запрос
снимается, в журнал пишется код 3, работает прежнее приложение. Без этого запрос
повторялся бы при каждом включении.

Без кнопки загрузчик запускает приложение при любом итоге проверки журнала, если
приложение целое (CRC, стек, векторы). Отказ внешней Flash не оставляет исправный
контроллер в загрузчике без связи с сервером.

Журнал: +0 начало, +4 завершение, +8 откат, +12 код ошибки, +16 очистка кандидата.
Слово +20 пишет только рабочая FW: код 3 или 4 отправлен серверу. Без этой отметки
ошибка уходила бы после каждого перезапуска. Следующий запрос обновления стирает
журнал вместе с отметкой.

## Аппаратные профили

| Профиль | HW ID | Вход загрузчика, замкнуть на GND | USB pull-up | SPI CS | LED |
|---|---|---|---|---|---|
| v5 | 139 | PA13 | PA8 | PB12 | PB8 / PB6 |
| MODEM | 139 | PA13 | PA8 | PB12 | PB8 / PB6 |
| MINI | 11 | PB1 | PB14 | PA4 | Мигание отключено: линии общие с CAN |

Это варианты `RELEASE_ON_MINI_PCB`/`RELEASE_ON_MODEM_PCB` старого кода, а не
доказанное соответствие каждой маркировке v1/v2/v3. Старые MODEM и v5 имеют
одинаковый ID 139; автоматически различить их по этому байту нельзя.
Перед стендовой прошивкой сверить вариант с платой, питание/кварц и цвета LED.
Реальных проверок GPIO, USB и SPI на контроллерах пока не было.

## Исправления по схемам и подключение программатора

В версии 0x31 профиль MINI не переключает PB8/PB9 для индикации. По схеме v1
PB8 — CAN_RX, выход внешнего трансивера; он оставлен плавающим входом STM32.
PB9 — CAN_TX; перед включением выходного драйвера выставляется высокий уровень
(состояние покоя). Мигание TXD создавало бы активность на CAN, поэтому его тоже нет.
На MINI режим загрузчика проверяется через USB/команду идентификации.
Двухцветная индикация из ТЗ на этой разводке без воздействия на CAN не реализуется.
На v5/MODEM остаётся переключение PWRLED/DATALED. Цвета зависят от установленных
светодиодов; синий цвет схема v5 не подтверждает.

Разъём X4 на схемах NEXT v5 / IP v3:

| Контакт | Сигнал | Подключение |
|---|---|---|
| 1 | 3,3 В | VTref программатора, не произвольный выход питания |
| 2 | SWDCLK / PA14 | SWCLK |
| 3 | SWDRST / PB4 | НЕ системный NRST; для SWD оставить свободным |
| 4 | GND | GND |
| 5 | Не подключён | Оставить свободным |
| 6 | SWDIO / PA13 | SWDIO |

Для Connect Under Reset нужен настоящий RST/NRST. На v5 его можно взять со стороны
RST кнопки SB1 (не со стороны GND); это вывод 7 микроконтроллера. SB2 «Загрузчик»
замыкает PA13/SWDIO на GND. Не удерживать SB2 во время обмена SWD.
На v1 разъём другой — X2; таблицу X4 к нему не применять.

Схемы указывают STM32F103CxT6, не уточняя плотность памяти. Перед прошивкой проверить
маркировку и объём Flash. Текущая разметка требует 128 КиБ. Загрузчик читает 16-битный
заводской регистр по 0x1FFFF7E0 до запуска USB. Если значение не 128, он не читает
образ внутренней Flash, не запускает его и не стирает/пишет приложение; идентификация
и начало USB-загрузки возвращают ошибку 7. Самомиграция приложения также запрещена.
Это не превращает сборку в прошивку для 64-КиБ MCU: неподходящий бинарник через SWD
записывать не следует. Разметка приложения и лимит загрузчика 32 КиБ не изменены.

Источники: «Схема ДОМОВОЙ NEXT_v5.pdf», «Схема ДОМОВОЙ IP_v3.pdf»,
«Схема ДОМОВОЙ IP_v1.pdf», «Схема ДОМОВОЙ IP_v1_обновленная.pdf» из папки
«СофтЭксперт/Для новой системы/Схемы устройств». Архив v3.1 не подтверждает
соответствие конкретной платы: его соединения отдельно не проверены.

## USB и сервисная утилита

Установить `pyserial` для работы с COM-портом. Вход: зажать вход BOOT и включить
питание. Файл приложения — чистый код с векторами, связанный по `0x08008200`,
с именем `HW.FW.UNIX_TIMESTAMP.bin`, например `139.14.1726300000.bin`.

`python boot_tool.py inspect <файл>` — проверить файл без подключения.
`python boot_tool.py upload COM5 <файл>` — явно отправить его на устройство.
Ответ «accepted» подтверждает приём; результат установки проверяется по версии
запущенного приложения/регистрации на сервере.

Кадр: `SLGT`, длина тела uint16 LE, тело, CRC16 Modbus тела.
Тело запроса: AA, команда, данные. Ответ: 55, команда, статус, BOOT, HW,
резерв, принято uint32 LE (всего 10 байт). Команды:

- 00: идентификация.
- 20: размер uint32, CRC32 uint32, имя файла с завершающим NUL.
- 21: смещение uint32 и 1–256 байт данных. Последовательные блоки;
  повтор уже принятого блока разрешён, если данные совпадают.
- 22: закончить загрузку и установить образ.
- 23: прочитать сохранённую ошибку установки.

Старые команды прямой записи внутренней Flash не поддерживаются. Старый загрузчик
остаётся совместим с пакетом переходной прошивки, но старое сервисное ПО не умеет
новый USB-протокол. Утилита не является законченным графическим сервисным ПО из ТЗ.

## Переход со старого загрузчика

Адресация приложения сохранена. Старый конфигуратор и старый загрузчик сначала
устанавливают обычную новую FW. В неё не встроен загрузчик; автоматической замены
при запуске нет. Конфигурация Migration_v5 удалена.

Затем пользователь вручную выбирает файл загрузчика по фотографии платы в новом
сервисном ПО. Рабочая FW принимает отдельный BIN по USB, проверяет размер 32768,
CRC, векторы и ID выбранного файла. Старый HW не используется для выбора или
проверки соответствия реальной плате. До нового загрузчика HW в метаданных равен 0.
После замены рабочая FW читает HW из нового загрузчика.

Новая команда сервисного протокола 110 принимает BEGIN/DATA/COMMIT/CANCEL/STATUS.
Это расширение для интеграции: имеющийся NextConfig ещё не вызывает эту команду.
Полное описание — MANUAL_UPDATE.md. Серверный канал не может заменить загрузчик;
команды 19/20 остаются для рабочей FW. Во время ручной передачи они блокируются.

Файл сначала сохраняется во внешнюю Flash, затем переносится во внутреннюю из RAM
с буфером 1 КиБ. Страницы приложения не стираются. Загрузчик допускает старый
заголовок приложения без доверия к его HW, но проверяет размер, векторы и CRC.
Для нового формата заголовка проверка HW остаётся строгой.

Состояние разрешения ручной записи хранится только в RAM. Отключение питания до
начала перезаписи не запускает её автоматически после рестарта: нужна новая
ручная операция. Потеря питания или отказ памяти во время перезаписи самого
загрузчика может потребовать SWD. Это не покрывается откатом приложения.

Готовой новой рабочей FW нет: полная сборка приложения в IAR ещё не выполнялась.
Текущий аппаратный адаптер приложения использует SPI1/CS из board.h (v5);
другие платы требуют соответствующего порта рабочей FW и стендовых испытаний.

## Проверки

`python tests/run_tests.py --cc <gcc-или-zig.exe>`: реальные C-модули установки
и USB-парсера на модели NOR Flash; 466 точек полного/частичного сбоя питания,
неверные CRC/HW/размеры, откат, отказ записи резервной копии, повтор
восстановления, максимальный образ,
разбиение USB-кадров, мусор, переполнение, повтор блока, преждевременный commit.
Python-тесты проверяют CRC-векторы, упаковку для старого загрузчика и вложенный образ.
Эта модель не заменяет испытания таймингов Flash, питания и периферии на плате.

Дополнительная проверка исполняемого ARM-кода: установить Python-пакет `unicorn`,
затем после сборки трёх профилей запустить
`python tests/test_platform.py --nm <путь-к-arm-none-eabi-nm.exe>`.
Проверяются стартовые конфигурации GPIO, отсутствие кратковременного выхода PB8,
отсутствие переключений CAN при обслуживании watchdog, сохранение индикации v5/MODEM,
отказ от работы с внутренней Flash при объёме 64, 0 или FFFF КиБ.
Это исполнение на модели регистров, не проверка электрических сигналов на плате.
