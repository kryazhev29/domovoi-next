ДОМОВОЙ NEXT: второй проход Thumb-2, 05.10.2026

Исходное состояние: 548d780, codex/comm-core, дерево domovoi-comm.
Рабочее дерево до начала было чистым. Чужих изменений и более нового HEAD
не было. Сохранён baseline ELF чистой Release-сборки 548d780.
Коммит реализации: 174d940.

Принято

1. fast_fnv10: FNV-1a ровно десяти байт внутри ix_bucket. Смешивание
   h^(h>>12)^(h>>24), маска, адреса корзин и формат индекса сохранены.
   Прежние idindex_hash и ASM CRC не переписывались.
2. fast_gf2_apply: RBIT/CLZ находит младший установленный бит; x&(x-1)
   удаляет его. Читаются соответствующие 16-битные столбцы матрицы.
   Выбран по полной crc16_ffInit, а не по одному удобному вектору.
3. fast_all_ff: ранний выход по грязному байту, выравнивание побайтно,
   затем только выровненные слова и ограниченный остаток. Внедрён в
   cfg_blank_sector и photo_prepare. Количество чтений NOR и вызовов WDT
   в подготовке фото сохранено, даже после обнаружения грязного буфера.
4. fast_sldn: первый полный SLDN либо совпадающий суффикс S/SL/SLD.
   При несовпадении сдвиг на один байт сохраняет перекрытия. Все чтения
   имеют проверку длины. Используется в server_rx_scan; CRC, длины,
   готовность кадра, единственное уплотнение и отложенное исполнение прежние.

User/fast_kernels.h содержит C-эталоны буферных функций. Прежний C gf2_apply
сохранён в crc.c. ASM_FAST_KERNELS включён в Debug и Release приложения,
загрузчик не менялся. Матрица GF(2) имеет обычное для uint16_t выравнивание;
байтовые буферы допускают любое выравнивание. Нулевые длины не читают память.
Все четыре новых ядра — листовые AAPCS, без стека, RAM-таблиц и записей.
Возвращаемый fast_all_ff bool каноничен: строго 0/1.

Сравнение отдельных функций

Единица — исполненные инструкции Unicorn 2.1.4, НЕ такты и НЕ время платы.
IAR compiler/assembler/linker 9.50.1 из каталога Embedded Workbench 9.2.
C собран с -Ohz и -Ohs; DLIB small соответствует библиотеке Release.
Измеряется вход в функцию до возврата включительно. Вызов вызывающей
функцией и её преобразования отдельно учтены в сравнении полного ELF ниже.

Ранние выходы и выравнивание

- 0xFF/256 в ASM: 412/410/408/406 инструкций при адресе mod4=0/1/2/3.
  Первый грязный байт — 6, нулевая длина — 3. Проверены все длины вокруг
  границ слова, 32/64/256/4096 и максимальные 65535, грязные позиции и биты.
- В cfg_blank_sector первая грязная позиция: 20 -> 24 инструкции вместе
  с вызовом; позиция 1: 28 -> 31; позиция 4: 52 -> 54. Это принятый
  небольшой регресс раннего отказа ради чистого сектора 33543 -> 8776.
  Чистая проверка — штатный успешный путь после стирания. Время NOR не мерялось.
- Внедрение fast_all_ff в log_blank отклонено: пробный bool-вариант давал
  на первом грязном байте 7 -> 11 инструкций и стек 0 -> 8 байт (чистая
  запись 260 -> 82). Для обычных заполненных записей это не полезно.
  Итоговый log_blank полностью сохранён; 33 сценария ELF подтверждают
  прежние результат, число инструкций и стек.
- ASM ID10 отклонён: развёрнутый C даёт те же 42 инструкции при равенстве
  и позднем отличии; выигрыш ASM только 0–1 инструкция на ранних выходах.
  Цена ASM 88 байт, столько же у C -Ohz. Существующая memcmp оставлена.
- FNV10 ASM равен C -Ohs по инструкциям, но занимает 76 против 120 байт;
  против C -Ohz развёртки выигрывает 41 -> 34 и стек 8 -> 0.

Проверки

- Первыми запущены исходные crcff/idindex/serverrx/photo и чистая Release.
- 74016 сравнений вариантов C/ASM с независимыми Python FNV/GF/байтовыми
  эталонами; ABI r4-r11/SP, все выравнивания байтовых входов, GF mod4=0/2.
- 9456 проверок точных диапазонов чтения и отсутствия записей у выбранных
  ядер; то же на итоговом ELF. Все их многобайтные загрузки выровнены.
- GF: все 65536 векторов на независимой матрице, отдельно в тестовом
  образе и итоговом ELF. Случайные матрицы, базис, нули и единицы — отдельно.
- C: 536 проверок у незамапленных краёв страниц, неизменность входов.
  Read-hook Unicorn нарушает исполнение библиотечной memcmp с IT-блоками
  (воспроизводится и на неизменённой IAR-библиотеке), поэтому для C значения
  и ABI проверены без этого hook, границы — guard pages. Это ограничение
  инструмента не скрыто как ошибка прошивки. Для принятого ASM read-hook
  работает; точные побайтовые границы проверены для каждого выравнивания.
- Новые критические условия: 15/15 мутаций ASM обнаружены; менялись копии
  файлов во временных каталогах, включая выход за границу и потерю верхних
  битов GF, пропуск хвоста FF, неверные частичные/перекрывающиеся SLDN.
- Все 61 группы run_all проверены. Первый общий запуск под PYTHONUTF8=1
  дал 59/61: SMS-фикстура CP1251 не декодировалась, поэтому не дошла и
  соответствующая группа мутаций связи. Обе группы повторены успешно без
  этой переменной; остальные успешные группы без причины не повторялись.
- Фото: 51/51 мутаций; хранение: 6/6, config 24725 обрывов и 336 ошибок
  чтения. Индекс: 5/5; восстановление: 16/16. Связь/сервер/ARM -Werror PASS.
- После уточнения bool API/отказа от log_blank повторены затронутые
  storage/photo/logcommit и обе группы асинхронного хранения — PASS.
- Прежние ASM CRC: 9216 сравнений, 3/3 мутации; прежний idindex_hash:
  20480 сравнений, 3/3 мутации. На окончательном ELF: CRC 1000 и hash 4096.
- Итоговый ELF: 256 случайных адресов корзин (128 каждого ELF), точные
  результаты/ошибки индексного поиска; сектор FF/грязь/отказ; 264 сравнения
  сборщика с исходным ELF. Host-сборщик: 5000 дифференциальных сценариев,
  разбиения кадров, хвосты, CRC, вложенный ввод, таймауты и повтор.
- CRC FF: по 200 независимых проверок обоих ELF, до полной 32-битной длины.
- Последняя полная IAR Release -build выполнена ПОСЛЕ всех мутационных
  прогонов: 0 ошибок, одно прежнее Ls016. Последующие проверки исходники
  не мутируют. Модели итогового W25, peripheral waits, persistence и storage
  faults PASS. W25 poll по-прежнему максимум 983 инструкции модели.
- git diff --check PASS; Bootloader, адреса и текущий протокол не менялись.

Ограничения

Вложенные ложные заголовки ускорились только на 1,3%: повторные CRC остаются,
3,52 млн инструкций за проход не доказывают задержку до 50 мс. Нет общего
множителя ускорения прошивки. Условия Flash и ожидание периферии в эти
числа не входят. Сохраняются ограничения асинхронного хранения из
ASYNC_STORAGE_20261005.txt, включая занятый NOR, повреждённый индекс,
синхронные пути и конечную RAM-очередь. Плата, COM, сервер, SMS, реле,
прошивка устройства и установочный пакет не использовались.
