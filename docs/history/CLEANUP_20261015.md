Оценка дополнительного состояния кольца — 8–16 Б RAM; размер машинного кода без реализации не измерен. ## Б. Два журнала секторов

`sector_journal_runtime.o`: **864 Б кода**, 0 Б статической RAM; `sector_runtime_runtime.o`: **808 Б кода + 128 Б RAM**. Они используют один формат и общие границы/CRC, но обслуживают разные контексты: синхронный старт/восстановление и `mem_patch2` против ограниченного фонового автомата с отменой и владельцами W25.

Повторяется последовательность compare → DATA → commit → target → clean. Прямо удалить один модуль нельзя. Измеренная верхняя граница убираемого синхронного пути записи: `sj_replace_pages` 204 + `sj_pages_equal` 78 + `sj_page_equal` 62 = **344 Б до добавления переходников**. Остальное требуется восстановлению; это не экономия всех 864/808 Б. Потребуются синхронная прокрутка, источник 256→64 Б, согласование busy/ошибок и запуска до executor. Точный чистый выигрыш не измерен, статические 128 Б остаются. Риск средний; до заморозки не объединять.
