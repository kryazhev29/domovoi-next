# Проверка периферии — 22.10.2026

База: `32a790e`, ветка `fix/review-49b4d1d`. Продолжение поручения владельца
по второму приложенному отчёту. Плата, настройки и сервер не затрагивались.

## Исправления и границы

1. **LED:** новый рисунок применяется на ближайшем шаге led_fun100ms, без
   доигрывания 1,6 с старого рисунка. Повторная загрузка того же значения фазу
   не сбрасывает. led_set удалён: при немедленной замене достаточно led_reg.
   Это не прямое включение GPIO из main: до первого шага главного цикла вывод
   остаётся в стартовом состоянии.
2. **ID Flash:** result изначально FFFF, после чтения проверяется spi_ready.
   Таймаут TXE/RXNE на любом из двух байтов или BSY после последнего байта
   возвращает FFFF, даже если стек/частично прочитанные данные похожи на 17EF/18EF.
3. **Пустой импульс реле:** activ=0 либо period=0 останавливает автомат, сохраняя
   текущий уровень выхода. Последующие out_process его не изменяют.
   Валидные импульсы, повторения и последняя пауза не менялись.
4. **NVIC:** PRIGROUP задаётся только board_init. Удалены записи из USB и USART1,
   USART3/DMA больше не выбирают кодирование по текущей группе. USBWakeUp
   переведён на уровень USB, чтобы он не делил высший уровень с PVD.

| Источник | Байтовый приоритет | Приоритет вытеснения |
| --- | --- | --- |
| PVD | 00 | 0 |
| EXTI2/EXTI3 Wiegand | 10 | 1 |
| USB LP / USBWakeUp | 80 | 8 |
| USART1 / USART3 / DMA1 Channel3 / SysTick | F0 | 15 |

PRIGROUP=3: четыре реализованных бита отданы вытеснению, подприоритетов нет.
Основание: [ST PM0056 Rev 7, таблица 45, страница 135](https://www.st.com/resource/en/programming_manual/cd00228163.pdf#page=135).
Wiegand D0/D1 не вытесняют друг друга; UART/DMA и их миллисекундное обслуживание
также остаются на одном уровне. USB таймер обновляет общие данные под PRIMASK.
Вложение IRQ стало глубже намеренно; аппаратный максимум стека не измерен.

5. **WG_process:** пустой приёмник не закрывает IRQ, не читает время и не
   перезаписывает wgTime. Уже собранная очередь продолжает обрабатываться,
   даже если wgBitCount=0. Первый новый фронт вокруг быстрой проверки не теряется.
6. **uart_clear:** сбрасывает только счётчики/состояние. Единственный прикладной
   вызов отбрасывает ненужный кадр; разборщики используют явную длину, очистка
   содержимого и нуль-терминатор им не нужны. Первый следующий байт пишется в начало.
7. **USB:** при пустом хвосте memmove пропускается. Непустой хвост, его возраст
   и граница протухшего префикса сохраняются.
8. Удалён spi_ssenable, исправлены комментарии таймеров и индикации, удалены
   висячие комментарии outs/hw_config. Указанных пустых блоков DOMOVOI_DIAG
   в текущих исходниках нет; действующие блоки диагностики сохранены.

## Проверки

- Семь режимов нового `test_iar_io_review.py` падают на базовом Release ELF
  и проходят на исправленных Release/ReleaseCustomer. Тест включён в --full.
- LED: оба канала, смена в каждой фазе, четыре рисунка, повторная загрузка.
- ID: настоящие SPI-функции, два корректных ID и пять вариантов аппаратного таймаута.
- NVIC: шесть порядков полной и повторной инициализации USB/UART, реальные IPR/SHP.
- Реле: оба выхода, изначально выключенный/включённый/импульсный режим,
  нулевая длительность/число повторов, 100 последующих шагов.
- Wiegand: host-перебор всех 2^24 ID, остановленная хранилищем очередь,
  первый фронт в тишине и EXTI на 526 границах инструкций активного разбора.
- UART: длины 0/1/64/512, исходный PRIMASK 0/1, сохранение буфера и следующий байт.
- USB: хвосты 0/1/64/511, отсутствие вызова memmove при пустом хвосте.
- 32 снимка периферии до/после: отличается только намеренно изменённый AIRCR.
  IPR всех затронутых IRQ дополнительно проверяются новым тестом.
- Полный `Tests/check.py --full`: Release 145/147, Customer 144/147, 604,70 с.
  Все 146 прежних результатов совпадают с проверенной базой 32a790e; новая
  группа IO review — PASS. Общий итог **FAIL** из-за прежних `recover mutations`
  (якорь stale-info-offline), `link call` (устаревшая базовая модель) и
  `diagnostics config` только в Customer. Эти ошибки не маскировались и не менялись.
- 222/222 протокольных контракта обоих профилей, dead_code и
  dead_code_regression — PASS. BIN/ELF/MAP, JSON/логи проверок, замеры и SHA256
  сохранены в `Binaries/IOReview_20261022/`; ELF копий совпадает с ELF из отчётов.

## Размеры и замеры ELF

| Профиль | BIN до → после | RAM до → после |

BIN загрузчика побайтно прежний. Набор диагностик IAR сократился на одно
предупреждение Pa082 в каждом профиле приложения; новых видов предупреждений нет.

| Операция | Инструкции до → после | Из них с закрытыми IRQ |

| Wiegand в тишине, Customer | 31 → 10 | 22 → 0 |
| uart_clear, 512 байт | 2074 → 13 | 2067 → 7 |

Это число исполненных инструкций модели, не такты/микросекунды на плате.
CSTACK сохранён 4096 Б. Локальный расход SP у WG_process: 32 → 40 Б;
у uart_clear: 16 → 0 Б; у usb_rx_consume: 24 → 24 Б. Wiegand с модельным
прерыванием при активном разборе использует 432 → 440 Б стека в Release.

Все аппаратные выводы требуют стендовой проверки новой сборки. Заливки не было.
