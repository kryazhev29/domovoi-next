# Этап 7: ОЗУ и завершение исправлений аудита

Ветка codex/mcu-audit, исходное состояние этапа `39dc2ef`, код после этапа `754277a`. Работа завершена локально по поручению «добивай все оставшиеся». Master, исходный worktree, платы, сервер и COM не использовались. Исходники прошивки cp1251/CRLF; ICF, адреса приложения, boot 32 КБ и формат обмена сохранены.

Для каждой правки перед исправлением показан отказ нового теста. После каждой правки выполнены все существовавшие host-группы, tx idle/reset/esof/busy/large, Bootloader/tests/run_tests.py и четыре IAR-конфигурации. Тесты размера mem/log первоначально добавлены вместе с таблицами USB, затем отдельно показаны падающими перед соответствующей правкой.

Вызов `mem_rewrite` с прежним четвёртым аргументом оставлен как совместимый вход; аргумент не используется. В рабочем коде нет malloc(MEMSECTORSIZE)/malloc(4096). Запросы к heap для ответов, SMS, фото и строкового состояния parser остаются; утверждение «вся прошивка больше не использует heap» неверно.

## Проверки страницы и восстановления

- `sectorjournal` и `bootjournal`: 24679 границ новой транзакции, 28776 повторного использования и 12306 восстановления, всего **65761** power-cut позиций на каждый адаптер. Проверены commit-bit cuts, повторные обрывы, 660 отказов чтения, 38 отказов erase/program, 256 повреждений metadata, соседние области и reserved/whitelist.
- `storage`: миграция 19 операций, обновление/config+device/reuse 37 операций, обрыв на каждой границе байта. Старый читатель, rollback, CRC/generation wrap, 12 циклов new/old и отсутствие лишних записей для неизменённого образа проходят.
- `test_iar_cmd13_heap.py` запускает настоящий `sync_write_cells`: все 1..63 ID, переход sector → другой sector → первый sector, повтор ID, сохранение first-pass/done. Запросов heap нет; измеренный стек этих путей **1080 Б**.
- `test_iar_page_heap.py`: реальный config/device и изменённый ID, модель NOR, нет запросов heap; измеренный максимум **1112 Б**. `test_iar_sector_journal.py`: recovery app/boot **624 Б**, обновление ID работает при полностью занятом heap и не течёт.
- Дополнительные IAR-тесты UART ownership, byte splits/NUL/binary tokens, ошибки allocator, таймеры, Q5 ACK/перезапуск, persistence, stack mark и CRC проходят. `test_iar_stack_diag.py` проверяет полный USB-запрос/ответ 111, поле 57 и CRC.

Финальный обязательный прогон: **44 host-группы PASS**, все пять tx сценариев PASS, загрузочные тесты PASS. DomovoiNext Release/Release_IPv3 и DomovoiBoot Release/Modem_Release: **0 ошибок**. Новых предупреждений нет: app — прежние Ls016 USB_Init и Ls017 gsm_dataread; boot — прежние Pa082 boot_main и Ls016 USB_Init. Логи находятся в Release/phase7-<метка>-{host,boot,iar}.log, финальная страница — `pages-final3`, дополнительные IAR — `phase7-iar-extra.log`.

## Стек и последующее измерение

По карте этапа: Program entry **2288 → 2448 Б**, interrupt Total Use **336 → 336 Б**. Сумма после правки — 2784 Б, но отмечена рекурсия gsm_dataread/connection_received/server_rx_process/user_parse_comand/user_savereset и неизвестные USB indirect calls. Это **не доказанный предел** и не основание уменьшать CSTACK. Наблюдённые пути Unicorn тоже не покрывают все вложенные IRQ, hardware exception frames, main callback paths и реальную длительность операций.

Подготовлен [STACK_MEASUREMENT.md](STACK_MEASUREMENT.md). Команда 111/поле 57 проверена в Unicorn, на плате не запускалась. Резервы всех ICF сохранены.

## Загрузчик 0x32 отдельно

- Служебные USB tables и pointer qualifiers переведены в const также для boot.
- Общий sector journal получил page-reader API. Формат metadata, commit, destination whitelist, scratch 0x1F9000/0x1FA000 и алгоритм recovery прежние; boot использует recovery, page writer в загрузчике не нужен.
- Boot core, установка/проба/откат, команда 110, USB boot reply и footer не менялись. Оба BIN имеют 32768 Б, byte version по 0x08007FFC — 0x32.

## Что не сделано и почему

- Аппаратные проверки не выполнялись: плата/COM/сервер запрещены. Нужны реальные power-cut NOR, SPI timings/отказы/износ, watchdog, пик стека/вложенность IRQ, скорость UART и interleaving AT/URC при насыщении 2048 Б, USB enumeration/suspend/recovery, камера, ADC, реле/Wiegand и PVD 2,5 В.
- После удаления stash уменьшена общая ёмкость отложенного RX: поток, ранее помещавшийся в stash плюс UART, теперь может вызвать явный отказ/закрытие при насыщении. Проверить на стенде; скрытая потеря байта не продолжается как корректный кадр.
- Старый уже установленный boot 0x32 не обязательно содержит recovery этапа 5: один номер версии этого не доказывает. Для безопасного старого FW rollback необходим обновлённый загрузчик; на платы ничего не писалось.
- Q1–Q4/Q6 остаются вопросами утверждённого протокола, решения по догадке не внесены. Q5 реализован по ответу владельца.
- Дополнительные варианты вне согласованного этапа 7 (меньшее USB ring, меньшие CRC/scan chunks, резервы ICF) не включены: они требуют отдельных измерений пропускной способности/стека. Все позиции этапов 1–7 выполнены с указанными ограничениями.
