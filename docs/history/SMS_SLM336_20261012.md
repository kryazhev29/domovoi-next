# Приём SMS SLM336 — 12.10.2026

Папка `domovoi-exec`, ветка `task/exec`, база `ee0979b`.
Плата №1 и сервер не использовались; `compare/c-asm` не изменён.

## Причина и границы вывода

Подтверждённый дефект базы — `Modules/comm_sms.c:16`: отправлялось
`AT+CNMI=2,1,0,0,0`. Common V2.24, §8.12, печатная стр. 194, прямо ограничивает
`<mode>` значением `0` (описания 1–3 ниже не означают их поддержку).
В `sms_done`, базовые строки 169–171, любой отказ повторял тот же шаг через
30 секунд. `ready` оставался 0; ни начальный `CMGL`, ни `CMGR` не выполнялись.
Модель, отвечающая по этому руководству, воспроизводит симптом.

Это объясняет отсутствие `LOG_SYS_RECVSMS`, но не доказывает фактический ERROR
на плате №1: её AT-трассы нет, неизвестно, принял ли модем четыре сообщения
21:35–21:36. CSQ, LTE и работа TCP этого не устанавливают. Переполненная SIM
также могла удержать новые сообщения у оператора; её заполнение ранее не читалось.

Первичные источники: `MEIG_SLM3XX_Common_AT Commands Manual_V2.24.pdf`,
§8.5–8.13, и `MEIG-SLM3XX_AT Command Manual_EX_V1.08.pdf` в указанной владельцем
папке. Common подтверждает `CMGF=0`, `CPMS="SM","SM","SM"`, `CMGL=4`:
последний перечисляет все четыре статуса сохранённых SMS, но сам их не стирает.
Удаление выполняется отдельно, по индексу через `CMGD`. Разрешены SM, ME, MT;
фиксированное начало индексов с 1 руководство не гарантирует.

## Исправление

- `Modules/comm_sms.c:16,253`: CNMI заменён на `0,1,0,0,0`.
  Отказ именно CNMI включает готовность 2 и обзор; ошибки обязательных CMGF/CPMS
  повторяются через 30 секунд, поскольку без этих шагов неизвестны формат/память.
- `Modules/comm_sms.c:164,326`: разбираются used/total ответа установки CPMS.
  Начальный и периодический обзор SM/ME (15 секунд) читает сохранённые сообщения,
  включая полную SIM. Очередь остаётся из восьми элементов; переполнение
  назначает повторный CMGL. Флаг обзора снимается только при принятии AT-запроса.
- `Modules/comm_sms.c:120,129,196,246`: индекс 0 действителен во всех трёх местах:
  URC/CMGL, CMGR, CMGD. Старший байт очереди хранит SM/ME/MT; mem1 переключается
  перед чтением/удалением. mem2/mem3 остаются SM. Неудачная смена памяти не
  считается успешной. `CMS 321` чтения означает отсутствующую ячейку: её не
  выдаём за принятую SMS. Другие ошибки чтения/удаления сохраняют запрос до повтора.
- `Modules/comm_sms.c:62,143`: остаётся потоковый разбор без новой копии PDU.
  SMSC пропускается по длине; MTI должен быть DELIVER, MMS/RP не мешают;
  международный OA 0x91 с 11 цифрами и завершающим F сохраняет `+7…`.
  GSM 7 бит, UCS2 и UDH проверены. Битые цифры, сжатый/резервный DCS,
  неправильная длина UDH/UCS2, лишние октеты и незавершённый hex не исполняют команду.
- `Modules/comm_sms.c:153,268`, `User/c/user_sms.c:23`: даже битая PDU при OK
  получает существующее событие `LOG_SYS_RECVSMS` перед удалением, с номером,
  если он разобран. Текст битой SMS пустой. Короткий/отсутствующий номер дополняется
  нулями до поля журнала 10 байт. При полной очереди журнала SMS ждёт записи события.
  Флаг первого вызова сбрасывается после успешной постановки события, поэтому
  занятость флеш или `smsToAdmin` не создаёт повторные события.
- `Modules/comm_at.c:82,137,257,299,335`: неожиданная `+CMT` имеет отдельное потоковое
  тело URC, включая длинные PDU; оно не становится ответом текущей AT-команды.
  Свободный декодер принимает его. Если декодер занят чтением/доставкой предыдущей
  SMS, сохраняется уведомление для события без номера/команды. Второго PDU-буфера
  нет. Штатный `CNMI mt=1` использует сохранение и CMTI, а не прямую доставку CMT.
  Между заголовком и телом AT остаётся занят; обрыв тела в покое через 2 секунды
  даёт событие о битой SMS и обычное восстановление границ AT.
- `Modules/comm_modem.c:35,165,391`: код CMS/CME фиксируется вместе с результатом
  служебного запроса. Следующая команда запуска/TCP не может обнулить снимок,
  нужный диагностике и обработке CMS 321. Поле помещается в прежнем выравнивании.
- При смене сеанса снимается старая операция AT, настройка начинается заново;
  очередь сохранённых SMS и ожидающее удаление сохраняются.

Служебный слот назначается между AT-командами; голодания при TCP и статусах
не обнаружено на модели. Его арбитраж не изменялся. Common/EX не задают отдельной
грамматики PDU/CMTI для SMS через IMS; настройка VoLTE и сетевого домена не менялась.
Маршрут доставки МегаФон и аппаратный приём в LTE требуют проверки на плате.

## USB 111, только DOMOVOI_DIAG

Версия `v[0]` стала **7**, число uint32 — **75**, полный кадр — **311 байт**.
Прежние `v[1..66]` сохранены. Все слова little-endian; смещения от первого байта
`SLDN`. Команда в байте 8, `v[i]` начинается в `9+4*i`; CRC в байтах 309–310,
покрывает байты 4–308 по прежнему протоколу.

| Слово | Байты | Содержимое |
|---|---|---|
| v[67] | 277–280 | байт 0: шаг; байт 1: готовность; байт 2: последний результат настройки; байт 3: 0 |
| v[68] | 281–284 | младшие 16 бит: числовой CME/CMS последнего шага настройки, остальное 0 |
| v[69] | 285–288 | младшие 16 бит: SM used; старшие: SM total последнего CPMS |
| v[70] | 289–292 | число URC `+CMTI` с момента comm_sms_init |
| v[71] | 293–296 | последний корректный индекс: байт 0 индекс, байт 1 память (1 SM, 2 ME, 3 MT), старшие байты 0 |
| v[72] | 297–300 | число заголовков записей CMGL; повторный обзор увеличивает снова |
| v[73] | 301–304 | байт 0: результат последнего CMGR; байт 1: последнее поле PDU; старшие байты 0 |
| v[74] | 305–308 | число успешных CMGD; только подтверждённых OK |

Шаг: 0 CMGF, 1 CPMS, 2 CNMI, 3 завершено. Готовность: 0 настройка,
1 CNMI OK, 2 CNMI отказал, работает обзор памяти.
Результат AT: 0 OK, 1 ERROR, 2 CME/CMS, 3 prompt, 4 timeout,
5 line overflow, 6 UART error, 7 bad frame, 8 bad length, 9 sink error;
255 — ответа ещё не было. Числовой код 65535 означает текстовый CME/CMS.

Поля PDU: 0 длина SMSC, 1 SMSC, 2 первый октет, 3 длина OA, 4 тип OA,
5 OA, 6 PID, 7 DCS, 8 SCTS, 9 UDL, 10 UDHL, 11 UD, 12 конец, 13 ошибка.
При ошибке сохраняется поле до перехода в P_BAD; при обрыве — достигнутое поле.
Отсутствующий заголовок оставляет начальное поле 0. Незавершённая половина hex
не исполняется, даже если поле уже 12. Неожиданная CMT использует тот же декодер
и может обновить поле PDU; результат CMGR относится именно к последнему CMGR.

**Интерпретация:** CMTI > 0 доказывает получение прошивкой уведомления о SMS.
Если чтение/удаление не продвигается, смотреть готовность и результат CMGR.
CMTI = 0 само по себе не доказывает, что SMS не дошла до модема:
URC могли не выдаваться/теряться, либо сообщение обнаружилось через CMGL.
CMTI = 0, CMGL = 0 и пустая SM после завершённого обзора означает, что модем
не предъявил сохранённых SMS; сеть и оператора эта диагностика не различает.
Полная SM подтверждается used == total > 0; записи CMGL при этом могут быть старыми.

CNMI mt=1 — SMS на SIM и `+CMTI`), памяти ME/MT и переключение `CPMS` (входящие идут
