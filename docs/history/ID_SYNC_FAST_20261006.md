# Синхронизация ID: C и ASM, 06.10.2026

База: `f92836e`, ветка `compare/c-asm`. Изменения не закоммичены. Плата и сервер не использовались. **Цель общего ответа за 300 мс не достигнута.**

Сделано: CRC читает только известную занятую часть ID; FF-хвост добавляется через общий `crc16_ffInit`. Его 15 повторяющихся аффинных степеней заменяют прежние 32 строки и построение матриц на стеке. Все 32 бита длины проверены независимым полиномиальным оракулом; формула совпала с первой реализации, стоп-условие не сработало.

CRC-опрос ограничен сменой миллисекунды и четырьмя кусками по 64 байта. В модели один SPI-read(64) требует 4390 инструкций драйвера плюс передачи 18 МГц; с CRC четыре куска укладываются примерно в 0,84 мс. Проверка часов выполняется после каждого куска. Это ограничение работы CRC, а не гарантия длительности всего главного цикла при произвольных IRQ.

`numbers`, `last`, `used`, XOR хешей обновляются по изменяемым ячейкам при единственном preflight-проходе журнала. Дубликаты индексов учитываются последовательно. Публикация — после verified всех секторов; индекс получает накопленную дельту и прежнюю фоновую перестройку. `id_watch_end` вызывается только для заменяемых записей, сохраняя консервативную раннюю границу. При неизвестном состоянии, ошибке или отмене команда 13 делает полный восстановительный проход и запоминает результат.

Команды 14/15 используют тот же бюджет для своих небольших областей. У них нет достоверной сохранённой границы заполнения, поэтому старшие ячейки не объявляются пустыми по последнему пакету. В 16 известный FF-хвост после заменённого списка также вычисляется формулой. В 17/18 пакетированы чтения и убраны отдельные проходы цикла для каждого бита FF-хвоста. При неизвестной границе 17/18 сохраняют полный путь чтения; восстановление метаданных и запоминание границы выполняет путь 13.

Журнал, его переходы, владение Flash, отмена, время BUSY W25 и порядок verified/ответа не изменены. Нового статического состояния или heap нет. В фазе CRC буфер `sjr.data[64]` свободен и заменяет прежний стековый буфер; поля `table_job.sector` и `batch` после журнала используются как граница чтения и флаг восстановления. Наблюдаемый максимум стека модели: 376 → 328 Б, это не глобальная оценка всех сценариев прошивки.

**Проверки финального кода**

- IAR Release ASM и C: 0 ошибок, единственное предупреждение Ls016. Адреса приложения, векторов, heap и CSTACK сохранены.
- `python Tests/run_all.py --project ASM`: 67/67 PASS, включая питание и мутации.
- `python Tests/run_all.py --project C`: 67/67 PASS, включая питание и мутации.
- `c_vs_asm_compare.py --paired`: 198 сценариев на вариант, 0 расхождений. Дополнительно проверен C_SPEED как диагностическая сборка; размеры и ограничения выше относятся только к штатным Release.
- Новые сценарии: пустая база, 3000 ID, 50 048 ID, неизвестная граница, разрыв питания внутри записи сектора и повтор пакета. Байты ответа и полные образы NOR совпадают с выполнением старого ELF из f92836e; дополнительно CRC проверена независимым полным проходом Python.
- Дубликаты, дырки, не-FF ячейка с индексом FFFF, повтор пакета без износа и повтор после восстановления неизвестной границы — PASS.
- Мутации исполняемого образа/границы: занижение занятого конца, пропуск FF-хвоста, превышение числа кусков, отключение миллисекундного ограничения — 4/4 обнаружены в каждой сборке. Прежняя мутация аффинного XOR перенесена в общий CRC-helper.
- Проверки выполнены после последнего изменения логики; итоговые SHA-256 ELF и подробные результаты сохранены в JSON.

**Что не получилось и ограничения**

1. Общий ответ ≤300 мс не получен ни для одной из трёх заполненностей. Уже один сохранённый секторный журнал даёт около 0,555 с в этой модели. Четыре стирания по 45 мс и 130 программирований по 0,7 мс занимают 271 мс без SPI, проверок и ожиданий проходов цикла. Ускорение только CRC этого предела не устраняет.
2. При полной базе FF-хвоста нет. Даже идеальное чтение 1 601 536 Б на 18 МГц требует 711,794 мс, без драйвера и CRC. Для гарантии 300 мс нужен иной алгоритм: сохраняемый CRC с поправками по изменениям, учёт всех писателей ID и отдельная переработка задержек журнала. Это выходит за выбранный приём «читать занятую часть», здесь не сделано.
3. Для 14/15 не добавлен новый кеш заполнения; для 17/18 не добавлено восстановление всех метаданных при неизвестном конце. Для обеих групп сохранена корректность старого полного пути. Гарантия 300 мс для этих команд не заявляется.
4. Модель не доказывает время на физической плате, при максимальных задержках NOR, занятости TX или нагрузке прерываний.

**Отдельное наблюдение о прежнем протоколе**
