## Поведение

RING и CLIP принимаются в любом порядке. Первый корректный номер передаётся прежнему `user_incomingcall` один раз; в том же такте ставится ATH. Команды ATA нет. Без CLIP через 1000 мс ставится ATH без действия. ERROR/CME/NO CARRIER вызывают аварийный CHUP; молчание ATH — CHUP через 1500 мс от отправки, до CMEE. Занятая флеш откладывает проверку доступа, но не обслуживание уже отправленного отбоя.

Повторные URC не дают нового действия/ATH. Сохранена граница вызова по 8 с тишины; другой номер после завершённого известного вызова допускается сразу. Поздний CLIP после сброса вызова без номера игнорируется. Новый вызов того же номера после границы снова проходит через прежние доступ, журнал и паузу выхода. Во время паузы второго импульса/события действия нет. Бит 11 не запрещает вызовы; VoLTE не изменён.

Живые PDP/TCP не закрываются и не переоткрываются; опросов сети/PDP/TCP после отбоя нет. При независимо обнаруженной потере связи сохранено обычное восстановление. Отбой ждёт окончания уже начатой AT-команды и передачи тела после `>`.

Локальный файл: [MEIG_SLM3XX_Common_AT Commands Manual_V2.24.pdf](C:/Users/kryaz/Desktop/мк/СофтЭксперт/Для%20новой%20системы/документация%20на%20GSM%20модемы/AT%20команды%20для%20модуля%20MEIG336/MEIG_SLM3XX_Common_AT%20Commands%20Manual_V2.24.pdf).

- §7.3, печатные стр. 147–148 (PDF 148–149): ATH завершает вызов; примечание явно допускает состояние ringing, результат OK. Для establishing указан ERROR. Таблица: Success OK, Fail ERROR; URC `CIEV:SOUNDER 0`, `CIVE:CALL0` приведены с написанием руководства.

## Ограничения

Плату не прошивали, модем, тарификацию и непрерывность связи у оператора физически не проверяли. RING/CLIP не несут ID вызова: без 8 с тишины новый звонок того же номера неотличим от повтора URC и подавляется по прежнему правилу. Произвольно зависший модем или уже запущенный долгий AT-запрос не дают гарантии немедленного физического отбоя. Срок 1000 мс относится к постановке ATH при отсутствии CLIP; свободный AT отправляет его в том же такте.

Загрузчик, адреса 0x08008000/0x08008200, серверный протокол и исторический CALL_ANSWER_20261006.md не изменены. Загрузчик только собирается/проверяется штатным `check.py --full`.
