# Чистка блока «ЛОГИКА», 07.10.2026

База: `97b05d6`. Рабочее дерево: `C:\Users\kryaz\Desktop\мк\_worktrees\domovoi-logic`. Изменения не закоммичены по прямому поручению. Плата, сервер и копия `Domovoi_ФИНАЛ` не используются. Адреса заголовка `0x08008000` и векторов `0x08008200`, граница загрузчика 32 КиБ сохранены.

## Результат и границы

Холодный ASM и монолит удалены. HYBRID и C собирают одну тематическую C-логику: 16 файлов реализации, общий внутренний интерфейс и числовые причины обновления. Самый большой файл — `user_commands.c`, 591 строка. Во всех новых модулях — русский договор, назначение функций и комментарии к восстановлению после пропадания питания. Нет отключённого архива, `stage4_unused_*`, подмены libc или inline ASM.

Внутренние причины обновления числовые. Пока соседние `fw_service_runtime.c` и `Bootloader/app_update.c` используют строковый ABI, необходимы 35 строк `user_fw_compat.c`. Пустая `user_wait_stable_power` остаётся только потому, что её вызывает чужой `memory_runtime.c` через `memory.h`. Оба ограничения, двойная проверка готовности в чужом `table_runtime.inc`, старые тесты и перенесённые callbacks анализа стека закрываются точным диффом ниже. Он применён и проверен только во временной интеграционной копии; эти чужие файлы рабочего дерева не изменены.

Обязательные тесты рабочего дерева имеют два старых контракта: `test_hybrid_hot.py` требует удалённый ASM, `test_uart_timer.c` передаёт удалённый аргумент порта. Называть такой исходный `run_all` зелёным нельзя. Числа интеграционной копии выделены отдельно.

## Граф до конца user_init

`main → user_init → mem_recover/user_readconfig → user_setdefault/user_writeConfigAndDevice` при восстановлении или отсутствии конфигурации. `user_initvariables → user_readsavedinformation → upload_restore/store_restore/fw_resume_after_boot → user_saveindex → user_writeConfigAndDevice`. Затем `sched16_boot`, запись события сброса по питанию, app_boot_metadata, WG/RS485. Только в конце присваивается `store_runtime=1`.

До этой точки сохранены синхронное сохранение конфигурации/device, user_saveindex и восстановление. user_writeconfig отсутствует в фактическом графе и в BIN; старое имя в findings не является доказательством входа. USB настраивается раньше, однако `usb_check_data`, `gsm_check_data`, разбор AT и выполнение серверных команд вызываются в основном цикле после возврата user_init. IRQ собирают данные и тики, не выполняют команды обновления или выгрузки. Вызовы `fw_service_begin/fw_take_block/user_send_crc*/upload_ack/upload_finish` принадлежат рабочему циклу.
