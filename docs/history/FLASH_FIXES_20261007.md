# Точечные исправления внешней флеш — этап 2

07.10.2026; база `593f01d`, ветка `task/flash`. Коммитов, платы и сервера нет.
Полный исполнитель, очередь запросов и вытеснение отложены до следующего этапа.

## Исправления и тесты

Все новые сценарии исполняют связанный IAR ELF обоих профилей. NOR и транспорт
заменяются границами модели; проверка реле E01 использует настоящий `outs.c`.
Сценарии находятся в `Tests/asm/test_flash_fixes.py`, группа `flash fixes` в CASES/CORE.

| Ошибка | Было → сделано | ELF-тест |
|---|---|---|
| E01 | Пока владелец держал флеш, два W26 превращались в count=52. `user_loop` теперь снимает кадр независимо от флеш в FIFO на четыре пары «биты/длина». Доступ обрабатывает по одному кадру при свободной флеш. Пятый кадр увеличивает `wg_overflows`, четыре соседних сохраняются. | `wiegand`: реальные EXTI D0/D1, два W26 с паузами при owner=0x81; после освобождения обе карты по порядку, реальное реле включено. Пятый кадр отвергнут без порчи четырёх. При свободной флеш карта обрабатывается в том же проходе после 26 мс тишины. |
| E02 | Запрет таблиц с битом 7 публиковал отсутствие сцены. Теперь недоступность таблиц/флеш и отказ чтения хвоста, записи или праздников сохраняют выполненное состояние и pending. Отсутствие сцены выводится по прочитанным данным. | `scenes`: активная сцена и owner=0x81; состояние/выходы сохранены, чтений нет; после освобождения выполнен пересчёт. Отдельно три отказа чтения и последующий повтор. |
| E03 | Таймер 30 с выбрасывал готовый проверенный кадр. Теперь срок применяется только при `server_rx_ready==0`; существующая граница свободного места QIRD сохраняется. | `server_frame`: команда 2 ждёт 31 с, буфер заполняется до 2048, сверх него принято 0 байт; исходный кадр не повреждён, команда исполнена ровно один раз. Неполный кадр по-прежнему удаляется. |
| E04 | Результат записи rollback игнорировался. `app_trial_rollback` возвращает успех W25; секундный такт вызывает `user_savereset` только после проверенной записи. | `rollback`: два отказа записи, метка FF и reset отсутствует; следующая секунда записывает ноль и запрашивает reset. |
| E05 | Таймер снимался до попытки сброса при BUSY. Последняя секунда теперь удерживается до готовности команды; прямой занятый вход, включая SMS, ставит `timeToDefault=1`. Запрос снимается при старте сброса. | `factory_reset`: три занятые секунды и прямой вход не теряют запрос; освобождение даёт один старт. Операции самого сброса заменены границами теста. |
| E06 | Отказ журнала игнорировался, загрузчик получал reported без принятого события. `fw_event` возвращает результат приёма. Остальные FW-источники используют `fw_event_request`, проверяющий результат и удерживающий отказ в маленьком FIFO; `fw_event_poll` повторяет приём. Новые команды и секундные FW-переходы ждут FIFO. Ошибка загрузчика повторяется при регистрации и в секундном такте; reported ставится после принятия события. При отказе метки повторяется только метка. | `firmware_events`: 16 обычных событий, загрузчик с ошибкой 133 или откатом 137; reported остаётся FF до приёма. Отказ записи reported повторяется без дубля. Отдельно два runtime-события 133/137 сохраняют FIFO и задерживают новую команду. |
| E07 | `manual_stage_read` всегда возвращал 1. Теперь возвращает результат `mem_read`/W25. | `manual_read`: отказ=0, успех=1, граница области отвергается. |
| E08 | `manual_stage_write` всегда возвращал 1. Теперь возвращает результат `mem_write`/W25. | `manual_write`: отказ=0, успех=1, граница области отвергается. |
| E09 | `manual_stage_erase` всегда возвращал 1. Теперь возвращает результат `mem_erase_sector`/W25. | `manual_erase`: отказ=0, успех=1, неверное выравнивание и конец области отвергаются. |

FIFO FW занимает 11 байт: четыре пары «номер/причина», два индекса и флаг
принятого события загрузчика. Новые команды блокируются уже при первом отложенном
событии. Единственный текущий FW-владелец может добавить начало и завершение;
секундный timeout срабатывает один раз. Эти источники укладываются в четыре места.
Обычные источники журнала и его очередь на 16 записей не изменены.

E05 выполнена в прямо разрешённом минимальном объёме: **не терять запрос при
занятой флеш**. Команда 3 и SMS всё ещё отвечают по старому механизму, без общего
результата очистки. После первого сохранения по-прежнему не проверяются результаты
всех очисток и финального сохранения настроек. Честное завершение потребует
отдельного состояния сброса, результата и удержания ответа; здесь оно не введено.

## Мутации

`Tests/asm/test_flash_mutations.py`, группа `flash mutations` в CASES/CORE,
копирует исходники в TEMP, компилирует затронутые объекты и связывает отдельный ELF.
Рабочие исходники, объекты и основной ELF не меняются. Ошибка сборки/запуска
не считается обнаруженной мутацией: требуется падение соответствующего assertion.

| Мутация | Возвращённое старое поведение | Падающий тест |
|---|---|---|
| E01 | Gate флеш перед `WG_process` в `user_loop`. | `wiegand`: кадр остался в приёмнике. |
| E02 | `mem_tables_ready` в условии входа в сцену, перед сохранением pending. | `scenes`: активная сцена исчезла при owner=0x81. |
| E03 | Удалён запрет timeout для готового кадра. | `server_frame`: готовый кадр сброшен, свободное место изменилось. |
| E04 | Безусловный reset после вызова rollback. | `rollback`: reset при неудачной записи метки. |
| E05 | Таймер снимается перед вызовом, центральный BUSY-повтор удалён. | `factory_reset`: запрос снят/сброс начался при занятой флеш. |
| E06 | Результат приёма ошибки загрузчика игнорируется. | `firmware_events`: reported записан при полной очереди. |
| E06-runtime | Результат приёма runtime-события игнорируется, удержание удалено. | `firmware_events`: новой команде разрешён старт, события потеряны. |
| E07 | После чтения всегда return 1. | `manual_read`: отказ сообщает успех. |
| E08 | После записи всегда return 1. | `manual_write`: отказ сообщает успех. |
| E09 | После стирания всегда return 1. | `manual_erase`: отказ сообщает успех. |

## Общая проверка и пределы

После последней правки исходников `Tests/check.py --full` — **PASS**, 1102,38 с:
Release **109/109**, ReleaseCustomer **109/109**, загрузчик собран;
`dead_code_regression` и `dead_code` — PASS. Все 212 протокольных контрактов
для каждого профиля прошли. Все десять мутаций обнаружены на каждом профиле.
Итоги: `%TEMP%/domovoi-flash-build/check-summary.json`, `run-all-Release.json`
и `run-all-ReleaseCustomer.json`; исходники мутаций и логи — в `runs/*/flash-mutations`.
UTF-8 без BOM и CRLF проверены `Tests/check_comm_sources.py`.
Прежние Wiegand-стенды получили свободную физическую NOR и поля нового FIFO;
проверки чётности, шума и PRIMASK сохранены. EXTI проверен на 143 границах инструкций.

Форматы хранения, сектор-журнал, A/B, W25, адреса приложения и протокол на проводе
не менялись. Исключение в поведении ошибки — E07–E09: потребитель ручного обновления
теперь получает настоящий IO-отказ и существующий `MANUAL_IO=2`, вместо ложного успеха.
Фикстуры 212 контрактов не редактировались.

Модель E01 подтверждает отсутствие дополнительного такта ожидания до реле;
это не замер микросекунд на плате. Очереди конечны; переполнение Wiegand наблюдаемо.
RAM-события по-прежнему не переживают потерю питания до записи журнала; reported
связан с приёмом события в RAM, как требует этот этап, а не с его долговечностью.

Временные сборки, копии исходников мутаций и логи находятся в TEMP. В дереве
остался созданный Python-кэш `Tests/__pycache__` и `Tests/asm/__pycache__`:
автоматическая проверка отклонила его удаление (`blocked by policy`), в том числе
удаление только файлов `.pyc` без рекурсии. Индекс Git не изменён; `git diff --check` — PASS.

Итог: E01–E09 исправлены точечно, E05 — в разрешённом минимальном объёме.
