База: `028ddc5` (после блока 4), ветка `fix/review-49b4d1d`.
Поручение: проверить и исправить прошивку по пятому отчёту владельца
(доступ, ID, расписания, протокол 2, команды, фото, обновление прошивки, загрузчик).
Работа локальная: плата, её настройки и сервер не изменялись.
Бюджет перед правками: RAM без роста, дополнительный BIN не более 256 Б, загрузчик ≤32 КиБ.

## Что не менялось и почему

- **1.3 (решение владельца):** в режимах «Открывать всем» и свободного прохода по
  расписанию `user_access_ready` и `user_activateOut` ищут ID в базе, потому что
  известному ID и в этих режимах списывается проход и отмечается первый проход.
  Пока индекс не готов (стартовый скан ~6 с после включения, пересборка после
  команды 13), неизвестный ID открывает реле только после линейного перебора базы
  (до ~390 проходов цикла, около секунды на полной базе); команда 8 с неизвестным
  ID на это время удерживает очередь команд. Это задержка, не отказ. Убрать её
  можно, не считая проходы известным ID, пока индекс недоступен, — изменение
  логики доступа, которое требует решения владельца; код не менялся.
- **1.4, команда 105:** подтверждение до сохранения `moduleType` — прежний
  контракт с NextConfig (ответ, затем перезапуск); допустимые значения типа
  модема в прошивке — 0, 2, 255 (не 0, 3, 255), проверка не добавлена, пока
  конфигуратор не ограничит набор.
- **1.5:** маска `0x03FFFFFF` оставляет старший бит чётности Wiegand-26 в бите 24
  номера; так работают выпущенные прошивки и записанные ими базы — менять нельзя
  без миграции, что отмечает и сам отчёт. Серверу это учитывать при генерации
  номеров.
- **2.1:** выполнено в блоке 4 (`028ddc5`): `user_ids_scan` читает базу через
  `counter_base_read` и `fast_all_ff`.
- **2.2:** повторные `user_findID` за один проход обслуживаются кэшем `lookup`:
  это одно чтение 32 Б из W25 на вызов, а не перебор базы. Кэш ячейки в ОЗУ —
  +32 Б RAM ради микросекунд; не делалось.
- **2.4:** группы вне 1..64 читаются внутри области 4 КиБ и отвергаются по
  несовпадению номера; защита от чтения за границей уже есть, поведение не
  меняется — код оставлен.
- **Итоговые пять находок других блоков:** `RCC->CSR` читается в `user_init` до
  очистки (`user_main.c`), `RCC_ClearFlag` в проекте нет; `USART_To_USB_Send_Data`
  есть только в загрузчике, где нет диагностического лога; `W25_RESULT_BUSY` в
  `idindex_runtime.c` отсутствует, занятость обрабатывается результатом 1
  `w25_async_poll`. Пункт о `server1 == ""` относится к коммуникационному стеку
  и в этом поручении не проверялся.
