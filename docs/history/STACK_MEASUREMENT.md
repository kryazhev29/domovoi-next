# Замер стека на стенде: подготовка

В этой работе платы, COM и сервер не использовались. CSTACK=4096 и HEAP=5120 сохранены. Ниже порядок последующего аппаратного измерения, а не результат измерения на плате.

1. Зафиксировать используемый BIN, его SHA256, Release map, аппаратную ревизию, модем и параметры испытания. После каждого перезапуска stack_paint заполняет нижнюю свободную часть CSTACK меткой; результат относится только к текущему запуску приложения.
2. Получить диагностический ответ командой **111** через сервисный USB/NextConfig. Она доступна без PIN. Пример read-only запроса с uniqId=1 и timeout=0: `53 4c 44 4e 03 00 00 01 6f 21 bc`. CRC16 включает байты от length до конца body; кадр сформирован и проверен `test_iar_stack_diag.py`.
3. Проверить prefix SLDN, length, uniqId, command 111 и CRC ответа. При текущем ответе 58 полей uint32 little-endian поле **57** находится по byte offset **237** от начала кадра (`9 + 57*4`). Это число байт непрерывной нетронутой метки от начала CSTACK. Использованная глубина по метке: **4096 − field57**. Не путать с HEAP/общей свободной RAM.
4. Сначала записать значение после полной инициализации. В одном запуске выполнить нагрузки стенда: синхронизацию ID 1/63 и переходы сектора; таблицы 14–16; сохранение config/device; полный pending journal до времени сервера; выдачу/подтверждение 9/10; фото обеих поддерживаемых камер; доступ/счётчики; modem SMS/URC/AT; USB reset/suspend/reconnect. Базы и получатели — стендовые. После каждой нагрузки читать поле 57 и сохранять минимальное значение.
5. Повторить с одновременными UART/USB/Wiegand/SysTick IRQ, медленным/отсутствующим ответом модема и отказами/задержками SPI. Снимать field57 часто, чтобы не потерять минимум при reset. Отдельно проверять запуск, ошибки питания, watchdog и fault record. Повторить для Release и Release_IPv3 и аппаратных ревизий.
6. Указать минимальный остаток, повторяемость, reset/fault, покрытые пути и непокрытые режимы. Ненулевой остаток только на этих нагрузках не доказывает максимума. Учитывать рекурсию call graph, аппаратные exception frames и возможную вложенность IRQ; решение о резерве принимать по худшим измерениям с обоснованным запасом.

Показания field57 могут меняться и от самой диагностики; если достигнут 0, это отсутствие нетронутой метки, а не точная глубина за пределом резерва. Метка не является memory guard.

Карта текущего приложения даёт Program entry 2448 и interrupt Total Use 336 Б, с неполным графом рекурсии/indirect calls. Unicorn наблюдал 1056 Б CRC path, 1112 Б config/ID path, 1080 Б sync path и 624 Б recovery. Эти значения не заменяют стенд.

Поле 57 относится к приложению. Boot имеет отдельный CSTACK и свои IRQ; для него нужен самостоятельный замер. На основании приложения резерв boot не уменьшать. ICF этим планом не изменяются.
