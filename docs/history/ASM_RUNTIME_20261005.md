# Перенос runtime на ARM Thumb-2, 05.10.2026

Продолжение: [память и ограниченные служебные автоматы](ASM_MEMORY_BOUNDED_20261005.md).
Числа ниже относятся к предыдущему этапу. Прежние3808 heap были синтетическим

База: 3450335, codex/comm-core. Плата, COM, прошивка, сервер, SMS и реле не использовались.

## Этап A: ранее переделанная исполняемая логика

В IAR-проекте семь C translation units заменены самостоятельными ASM-модулями:
`user_fun`, `flash_w25`, `memory`, `photo`, `crc`, `idindex`, `user_comm`.
Перенесены целые модули, чтобы не оставлять C-условия вокруг ASM-ядер.
Полный список 309 функций — `asm/runtime_inventory.json` (по модулю).
Он включает server_rx_* (бюджет, CRC, reset, владение входом), w25_async_*,
mem_config_* и cfg_* (публикация/очистка/ошибки), store_* и user_storage_*,
log_async_*/log_storage_poll, fw_async_*/fw_storage_poll, crc16_append_ff,
ID-поиск/счётчики/хеш-обвязки, фото и вызывающие функции user_comm.

ASM получен из установленного IAR 9.50.1, проверен повторным ассемблированием
и хранится в репозитории. Обычная сборка **не компилирует C-эталоны** и не
генерирует ASM автоматически. Условия, циклы, ожидание, отмена и ошибки находятся
в `.s`. `Tests/asm/port_runtime.py` — явный инструмент воспроизведения переноса.
Устранена несовместимость listing с assembler: CFI FunCall вынесен перед IT;
инструкции IT-блоков сохранены. AAPCS/PRESERVE8/REQUIRE8 и CFI сохранены.

C-эталоны находятся только в `Tests/asm/reference/User`. В production C остались
объявления отладочных типов `User/runtime_layout.c` (36 байт readonly data)
и не затронутые этим переносом модули периферии/связи/загрузчика. В main и USB
прежние связующие вызовы сохранены. `User/sector_journal.c` пока общий неизменённый
startup/recovery и синхронный API; runtime таблиц заменяется следующим этапом.
Этот этап не объявляет таблицы или фотографии пошаговыми.

## Этап B: таблицы и секторный журнал

Команды 13/14/15/16 выполняют проверку длины и приобретают собственную копию
записей (до 2016 байт для сетевого кадра). Дальше их продвигает
`user_storage_poll`, без новых входящих данных. Старые `sync_write_cells`,
`mem_replace_pages`, `sj_replace_pages`, `holiday_write` остаются независимым
синхронным эталоном/служебным API; runtime команд больше их не вызывает.

Новые ASM-функции: table_runtime_active/blocks_reads/quiet/cancel/begin/poll/finish,
table_chunk, table_scan_begin, sj_runtime_begin/poll/cancel/reset/blocked,
sjr_start/fail, idindex_runtime_suspend. Изменены ASM вызывающие функции
user_parse_comand, user_storage_poll/command_ready/flash_ready, user_savereset,
store_usb_session, user_comm_session, mem_tables_ready. Резервная копия → CRC →
28 байт metadata → 4 байта commit → erase назначения → copy → CRC и побайтовое
сравнение → erase metadata. Формат SJ версии 1 и loader recovery не менялись.
Одинаковый сектор не стирается повторно. Для пакета, возвращающегося к прежнему
сектору, сохранён прежний порядок последовательных секторных транзакций.

Один шаг: callback/чтение/CRC 64 байта, максимум 128 прочитанных байт либо один
async start/poll. Callback рассматривает не более числа записей кадра (63 для
ID). Курсор группы меняется после verified; timestamp/CRC-ответ — после всей
операции. Отмена до commit оставляет назначение прежним; после commit завершает
текущий сектор и не начинает следующий. Reconnect/USB reset подавляют старый ACK.
Ожидание выходного слота ограничено 2 с. После неопределённого commit доступ к
таблицам закрыт до startup recovery, без синхронного recovery из runtime.

Индекс ID временно выключается, после проверки базы получает новые count/hash/end;
его прежнее фоновое восстановление сохранено. CRC всей ID-базы теперь требует
конечного полного прохода по 64 байта: это увеличивает общую работу и время
владения Flash, но ограничивает отдельный шаг. Другие владельцы Flash ждут;
главный цикл продолжает связь/таймеры. Программный reset отменяет таблицу и ждёт
освобождения NOR. Физический BUSY ограничивается прежними таймаутами W25, а не
циклом ожидания в автомате. Suspend/resume не используется.

## Этап C: фотографии и окончательная сверка ASM

Исторический аудит `asm/runtime_history.json` перечисляет 102 изменения функций
в 11 коммитах от начала переноса CRC до 3450335. Дополнительно выявлены и
перенесены `spi_wait_flag`, `usb_check_data`, `sj_flash_crc`, `sj_header`,
`sj_replace_pages` и целиком их модули. Итоговая инвентаризация
`asm/runtime_inventory.json` содержит **368 функций в 11 ASM-модулях**.
В ней перечислены также прежние RX/CRC, W25, config, очистка журнала/ID,
события, отложенные ответы/reset, FW, индекс и вычислительные обвязки.

Исполняемый код приложения берётся из самостоятельных IAR `.s`. ASM получен
экспортом установленного IAR 9.50.1 и повторно собран IASM; это не ручная
оптимизация каждой инструкции. C в Tests — спецификации/эталоны, исключённые
из проекта приложения. Проверены все байты text/data объектов, CFI,
PRESERVE8/REQUIRE8 и внешние weak-символы. При экспорте сохранён PUBWEAK для
USB callback: итоговый ELF действительно вызывает сильный обработчик приложения.
Private compiler COMDAT-подпрограммы могут занимать больше Flash после экспорта;
их инструкции сохранены. Независимая дифференциальная проверка фото исполняет
сохранённый C-linked ELF 3450335 и новый ASM ELF, сравнивая NOR целиком и пакеты.

Новые/переделанные ASM-функции фото:

- `photo_start`, `photo_prepare`, `photo_frame`, `photo_poll`, `photo_request`,
  `photo_request_answer`, `photo_connection_lost`, `photo_storage_busy`,
  `photo_storage_cancel`, `photo_storage_poll`;
- `pr_start`, `pr_prepare`, `pr_frame`, `pr_poll`, `pr_request`, `pr_data_ready`,
  `pr_write`, `pr_erase`, `pr_fail`, `pr_release`, `pr_scan_begin`,
  `pr_scan_finish`, `pr_send_begin`, `pr_cleanup_begin`;
- вызывающие `user_parse_comand`, `user_storage_poll`, `user_storage_command_ready`,
  `user_storage_flash_ready`, `user_storage_background_ready`, `user_savereset`,
  `store_snapshot`, `fw_async_begin`; прежние вспомогательные функции фото также ASM.

Команда 7 запускает ограниченный просмотр очереди и обмен с камерой.
Положительный ответ на 7 сохраняет прежний смысл принятия запроса, а не завершения
снимка. Подготовка места, проверка пустого хвоста, резервирование префикса,
CRC, публикация старого 16-байтового маркера, стирание назначения, восстановление,
проверка CRC назначения и очистка маркера разбиты на шаги по 64 байта/одну I/O.
Неизменный формат: 8 байт заголовка, 128 ACK-слотов по 8 байт, full-marker,
данные фото; два последних сектора раздела — резерв и metadata.

Блок камеры проверяется и копируется из UART/frame в принадлежащий операции
буфер. При переходе страницы W25 он делится на две записи. `written`, packet
и следующий запрос камеры меняются после verified всех частей. После последнего
блока отдельно проверяются size и datetime; только затем увеличивается count,
обновляется адрес и создаётся одно событие. Сохраняются прежние правила нумерации.
Физическая запись datetime не считается атомарной: при её обрыве старый формат
может дать увеличенный частичный номер, но данные уже проверены и запись
учитывается не более одного раза. Обрыв/отмена незавершённого снимка не публикует
его счётчик. После опубликованного commit операция доводит устойчивую часть.

Команда 21 копирует аргументы, просматривает ACK по 64 байта, записывает body,
затем marker, проверяет завершение и только после этого отвечает и меняет
подтверждённый курсор. Повтор не расходует слот. Выгрузка читает/считает CRC
по 64 байта в собственный heap-буфер 534 байта. Общий буфер связи захватывается
только для окончательной отправки. Reconnect/USB reset подавляют старые ответы.
Ожидание выходного слота ограничено 2 с; остановка потока камеры/выгрузки —
прежними таймаутами до 60 с. Нет необходимости получать новые данные для poll.

Очистка сохраняет старый intent и bitmap, стирает сектор через W25 async,
проверяет его и checkpoint, затем освобождает Flash. Сканирование metadata и
bitmap ограничено 64 байтами. Проверены частичные финальные erase metadata:
невалидный остаток intent очищает только metadata, не чужие сектора фото.
Ошибки после неопределённого I/O переводят фото в конечное закрытое состояние
до startup/recovery. Постоянную неисправность NOR нельзя превратить в успешную
операцию или гарантировать её завершение без восстановления оборудования.

Владение Flash единое: table/photo/FW/event/config продвигается только своим
poll. Фото и таблицы взаимно исключены и используют общий `sjr.data[64]`.
Ожидающие config и события получают обслуживание до следующего фонового задания
фото; очистка уступает между секторами. Reset отменяет снимок/таблицу, дожидается
уже начатого I/O и устойчивой части commit. Доступ и FW не читают/пишут NOR
поверх активного владельца. Дополнительно устранён старый BUSY spin из runtime
`w25_read_data`: после `store_runtime=1` только одна проверка статуса и отказ
при BUSY. Синхронное startup-ожидание оставлено отдельно. Suspend/resume нет.
