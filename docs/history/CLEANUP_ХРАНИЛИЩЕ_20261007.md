## Выполнение пунктов и безопасность

1. **Зеркало удалено.** Удалены cfg_mirror, cfg_prepare, cfg_legacy_crc, cfg_equal_flash, cfg_blank_sector, CA_MIRROR0/1, CA_TAIL, CA_DEVICE, CA_CONFIG. При первом стартовом чтении cfg_boot_select сначала проверяет A/B. Только если обоих целых слотов нет, проверяет CRC16 первых 510 Б config и device и переносит все 4096 Б старого образа в A. Старое место не стирается и не программируется. При наличии A/B старые настройки не получают приоритета, даже если их CRC целый. Неудачный перенос повторяется при следующем стартовом обращении; его источник остаётся целым. cfg_legacy_checked из строки 139 полного разбора удалён. Внутренний cfg_boot_done означает только завершённый стартовый выбор слота; фикстура настроек обращается к cfg_boot_select. Транспортные модели с заранее подготовленным образом выбирают старое/новое имя стартового признака, чтобы проверять и базовый ELF.
   - Байты: совместный результат memory −1106 / −1114 Б кода.
   - Безопасность: неактивный слот стирается первым; заголовок пишется последним; CRC образа и поколения проверяется после сброса.
   - Проверки: config_power; дополнительные 95 точек обрыва первого переноса и проверки отсутствия старых записей.

2. **Повторная проверка записи удалена.** В асинхронном журнале шаг 5 строит заголовок из CRC источника, шаги 7/9/14 больше не читают данные или заголовок. CRC SJ_DATA в заголовке сохранён. Синхронный журнал не вызывает sj_recover в начале/конце, не проверяет FF после проверенного стирания, не читает CRC/страницы назад после записи. sj_pages_equal оставлен только *до* записи для отсутствия лишнего стирания. sj_copy_data общий для переноса и восстановления. При восстановлении проверяется CRC SJ_DATA, затем назначение сравнивается с уже проверенным образом; отдельный CRC назначения и сравнение после проверенного копирования не нужны. В настройках cfg_pages_equal и полный cfg_valid после публикации удалены; сравниваются только изменяемые части до записи, CRC копии считается по источнику. Убран ix_add readback.
   - Байты: sector_journal −336 Б, sector_runtime −276 Б, idindex −40 Б; часть результата memory относится сюда.
   - Безопасность: вся физическая запись/стирание остаётся проверенной W25 и адаптером ID CRC. Ошибка journal I/O фиксируется mem_journal_result как запрет таблиц, включая прямой вызов sj_replace_pages из переноса старого журнала. Это обработка результата, без нового чтения. Источник живёт до окончания W25.
   - Проверки: table_power, expiry_power, stage5_log_power, stage5_crc_power, config_power; порча резервного образа после сброса отвергается до стирания; прямой sync journal с отказом записи блокирует следующую команду и восстанавливается после старта.

3. **Общий кадр SLDN и ответ 11.** packet_frame в packet.c — единственная сборка заголовка/длины/CRC. packet_send сохраняет немедленный транспортный контракт; reply_send сохраняет контракт собственного готового кадра автомата (USB_try и копия в серверный TX). answer11 перенесён сюда; timeout 5 команд 7/21 сохранён. idclear готовит success общим сборщиком; upload собирает CRC кадра после заполнения тела; service собирает кадр после CRC данных; fw_service собирает команду 4/253 тем же способом. Кадры готовы до ожидания канала и не меняются при повторе.
   - Байты: группа packet/service/idclear/upload/fw_service −350 Б кода совместно с пунктами 4/5/8.
   - Безопасность: тело и формат CRC прежние; захват серверного буфера и заимствование USB не меняются.
   - Проверки: service, upload, clear, firmware, owner_lifetimes, usb_replies; 18 ответов 11 сравниваются с BIN базы, включая каналы USB/server и команды фото.
   - user_send_answer_comand в чужих C и hybrid ASM остаётся прежним: ниже точные диффы его перевода на answer11.

4. **Внутренние повторные границы убраны.** Удалены проверки констант mem[] в expiry/idclear, переполнения mem_guard/mem_reserved, NULL/размеров mem_patch2, адреса/длины/выравнивания w25_async_start, адреса/reader sj_runtime_begin. В sj_io_* адрес проверяет заголовок восстановления или задаёт внутренний вызывающий; повторный sj_span не вызывается. sj_span сохранён в общем API для загрузчика. Условия владения, занятости, ошибки, CRC внешнего образа и ограничения внешних кадров остаются. w25_read_available проверяет SPI после чтения статуса; второе одинаковое обращение spi_ready до обмена удалено.
   - Байты: W25 −72 Б, expiry −70 Б (вместе с пунктом 6), idclear −76 Б (вместе с пунктом 3); остальные входят в совместный memory/sector_runtime.
   - Безопасность: mem[] задаётся в user_init; предел id_cells_end получен сканом основной базы. Внешний SJ-заголовок по-прежнему проверяет адрес назначения.
   - Проверки: stage3 input guards, stage5 2MB, clear/expiry, реальные W25/SPI сценарии service/firmware, правила и длины кадров.

5. **Store по полям.** store_state_s в runtime_internal.h описывает 32 Б состояния. Compile-time проверки фиксируют job=18, cmd=21, channel=22, uniq=23, quiet=24. fw_service обращается по полям, US_COMMAND задан именем STORE_JOB_COMMAND. Определение store остаётся в user_fun; общий тип для него дан диффом. Размещение ASM не меняется.
   - Байты: самостоятельная замена индексов на поля не меняет ABI или RAM; результат fw_service −48 Б включает пункты 3/8.
   - Проверки: четыре IAR сборки, firmware/firmware_power, handoff/owner_lifetimes, сравнение C/HYBRID.

6. **Expiry по 64 Б.** Снимок уменьшен до 64 Б и удерживает две записи ID. Чтение очередного фрагмента совмещено с обработкой первой записи. Время прохода фиксируется при запуске, запись ID проходит через журнал.
   - Байты: expiry −70 Б кода совместно с пунктом 4; живой workspace −960 Б, статический общий буфер без изменения.
   - Проверки: expiry full_scan_and_heap по 1 601 536 Б, отмены/ошибки/expiry_power; лимит 64 Б чтения за вызов и прежний лимит полного прохода выдержаны.
   - Поле crc в чужом sector_runtime.h больше не используется C-автоматом; не удалялось, чтобы сохранить общий ABI с замороженным ASM.

7. **Мёртвые функции удалены из C.** mem_rewrite, mem_erase_mem, mem_replace_sector, sj_replace, w25_clear_status, w25_erase_chip отсутствуют в своих исходниках. Проверены рабочие C/INC/гибридные S, EXTERN/PUBLIC/вызовы, векторы и указатели; рабочих входов нет. Старые тестовые имена не являются входами прошивки. Декларация sj_replace удалена в своём заголовке; чужие memory.h/flash_w25.h — дифф ниже.
   - Байты: исходные BIN уже не содержали эти функции — отдельная экономия 0 Б; удалён мёртвый исходник.
   - Проверки: IAR линковка всех четырёх вариантов/профилей, анализ ссылок и отсутствие удалённых символов в итоговом ELF. Исторический C host sectorjournal использует mem_replace_sector и требует адаптера к mem_replace_pages при самостоятельном запуске; project run_all заменяет этот fixture связанным table_power.

8. **Store_runtime разобран по реальному старту.**
   - memory: восстановление при !store_runtime **оставлено**. user_init → mem_recover → user_initvariables → user_getNumbersCount → mem_read/mem_guard → mem_tables_ready. При ошибке первого восстановления до конца user_init возможен повтор; это живая ветка.

   - fw_service: !store_runtime удалено. fw_resume_after_boot вызывает saveindex/проверки FW, но не fw_service_begin. Команда 19 поступает через тот же цикл после старта. Функция обслуживает запрос целиком; синхронный хвост её foreign caller мёртв и приведён диффом.
   - Байты upload/fw_service уже учтены в общей группе пункта 3, новые измерения не складываются повторно.
   - Проверки: main-idle и 205 парных сценариев, firmware/upload и startup/migration power tests.
