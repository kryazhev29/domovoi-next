# ПИН 4–5 цифр и универсальный ПИН — 07.10.2026

База: `79422c1`, дерево `domovoi-pin`. Реализовано решение заказчика от 06.10.2026; прежнее ограничение «4 цифры» в выгрузке протокола исправлено.

## Формат и переход

`config.pinCode` — число `0–99999`, `uint32_t` младшим байтом вперёд. Поле занимает прежние 4 байта со смещения 4 в `config_s`; размер настроек остаётся 512 байт. Заводской ПИН — число `4321` (`E1 10 00 00`), пример нового ПИНа `20140` — `AC 4E 00 00`.

`user_parse_pin` разбирает ровно 4 или 5 ASCII-цифр, при отказе не меняет результат. Ведущие нули допустимы: `04321 == 4321`, `0000 == 00000 == 0`. `user_pin_valid` сравнивает число с ПИНом настроек либо универсальным ПИНом. SMS и USB 102 используют эти же функции; неверный SMS-ПИН сохраняет ответ `Pin not valid`.

В `user_readconfig` переход выполняется только после успешного чтения и проверки CRC. Значение больше `99999`, состоящее из четырёх ASCII-цифр, переводится общим разборщиком: `0x31323334` (байты «4321») → `4321`, `0x34333231` («1234») → `1234`. Прочее значение больше `99999` заменяется только заводским ПИНом, остальные поля сохраняются. Числа допустимого диапазона не меняются.

Изменённый `config` получает новую CRC и сохраняется через существующий `mem_patch` → `mem_patch2` → атомарный A/B-владелец. Меняются только 512 байт настроек; сохранённый `device`, включая IMEI, остаётся побайтно прежним. Это необходимо потому, что на старте `user_readconfig` вызывается раньше восстановления `device`. Повторное чтение уже числового ПИНа не вызывает запись. При неверной CRC действует прежнее восстановление заводских настроек, ASCII не переводится.

Команда 12 принимает числовое поле и отклоняет значения больше `99999`; ASCII от сервера не мигрируется. Команда 106 выдаёт число в прежнем поле. В USB 102 длина текста берётся из кадра: `len - 3`, допустимы 4/5 цифр. Пайлоад из 3 цифр отклоняет существующая проверка минимальной длины, из 6 — общий разборщик. Прежний четырёхсимвольный ввод USB 102 сохранён. Признак заводского ПИНа в `send_buffer[24]` сравнивается с числом `4321`.

## Универсальный ПИН

Проверен исходник заказчика `git show 05e9248:User/user_fun.c`, декодированный как cp1251: `user_unipassword`, `user_imeivalid`, `UNIPASS_INITVALUE = 32768`.

Формула: `uint16_t(UNIVERSAL_PIN_BASE + 2*a + c - 3*b - d)`, где `a` — индексы IMEI 11..14, `b` — 8..10, `c` — 0..2, `d` — 3..5. Единственное именованное место константы формулы в рабочем коде — `UNIVERSAL_PIN_BASE` в `User/c/user_config.c`.

IMEI `867442070217472`: `a=7472`, `b=21`, `c=867`, `d=442`; `32768 + 14944 + 867 - 63 - 442 = 48074`. Приведение результата к 16 битам сохранено как у заказчика. Проверяются все 15 цифр, включая не участвующие в формуле индексы 6/7, и нулевой байт после них.

При пустом, коротком, длинном либо недесятичном IMEI универсального ПИНа нет. Возврат `32768` при неверном IMEI из старого исходника **не перенесён**: он открывал доступ без известного IMEI. IMEI из пятнадцати нулей соответствует оговорённому цифровому формату и даёт `32768`.

Универсальный ПИН принимается в SMS и USB 102, вычисляется по текущему IMEI, в настройки не записывается и командой 12 не изменяется. Это проверено после записи нового локального ПИНа `20140`.

### Мутации

Ошибки внесены только в отдельные копии исходников в TEMP; собран настоящий Release ELF, тесты читают его вместо рабочего образа.

| Мутация | Обнаружение |
| --- | --- |
| Удалён блок перехода `config.pinCode > 99999u` из `user_readconfig` | `pin_config` падает с кодом 1: остаётся `825373492` вместо `4321`. |
| Удалена проверка `length != 4u && length != 5u` из `user_parse_pin` | `pin_commands` падает с кодом 1: SMS с тремя цифрами `432` принят при локальном ПИНе 432. Отдельно подтверждён ошибочный приём USB 102 с шестью цифрами `004321`. |
| Сохранение только `config` заменено полным `user_writeConfigAndDevice` до загрузки `device` | `pin_config` падает с кодом 1 на проверке побайтной сохранности `device`. |

## Доработка архитектора

Сервер СофтЭксперт присылает ПИН командой 12 четырьмя ASCII-цифрами (копия настроек платы №1 от 07.10: байты «4321»). Отказ PARAMERROR на такое значение остановил бы синхронизацию настроек. Теперь `config_pin_number()` (один на чтение настроек и команду 12) принимает 0–99999 числом либо 4 ASCII-цифры и переводит их в число. Тест — команда 12 с 0x31323334 сохраняет 4321; мутация (старый отказ) — тест падает. Пятизначный ПИН сервер может передать только числом.
