База: `fabf212` (ветка `codex/comm-core`). Исходная сборка IAR Release совпадает с отчётом

Признак «задание существует» держится до отправки ответа, поэтому **готовый ответ, ждущий TX,
блокирует Flash для всех**, даже когда данные уже скопированы в свой пакет и транзакция Flash
закончена.

### Критический путь доступа

```
reader_id (Wiegand / RF433 / RFID) ─┐
user_incomingcall (телефон) ────────┼─> user_checkIdAndControl ─> mem_tables_ready
                                    │        └─> user_findID      (стек 1024, индекс; fallback = вся база синхронно)
cmd 8 с ID (сервер) ────────────────┴─> user_activateOut
                                             ├─> user_findID      (второй поиск того же ID)
                                             ├─> user_updateID ─> mem_read + mem_patch (синхронный журнал)
                                             └─> out_load (реле), затем события журнала
```

Измерено на `fabf212`: fallback поиска — 896288 инструкций модели и 1601536 байт чтения за
вызов; `user_updateID` — 394331 инструкция, 65666 байт чтения, 4 стирания, 34 программирования.
Порядок B25: **счётчик проходов сохранён (verified) до включения реле.**

## 2. Контракт владения Flash (задача 1)

Четыре разных понятия, каждое своим признаком:

| Понятие | Признак | Кто читает |
|---|---|---|
| A. операция существует (есть контекст, возможно ждёт TX) | указатель/состояние задания, как сейчас | только планировщик `user_storage_poll` и само задание |
| B. владение транзакцией Flash | **один байт `flash_owner`** (0 = свободно, иначе номер владельца) + бит «чтение тоже запрещено» | все проверки готовности |
| C. аппаратный BUSY NOR | `w25_async_active` / `w25_read_available` | только слой W25 и те, кто реально начинает I/O |
| D. ответ ждёт TX | состояние внутри задания | только задание; на Flash не влияет |

Правила:

1. **Захват:** `flash_claim(owner)` → 1, если байт свободен или уже равен `owner`; иначе 0. Без
   ожиданий, PRIMASK не нужен (только главный цикл), если ни один IRQ не трогает Flash — **проверить
   и записать**.
2. **Освобождение:** `flash_release(owner)` обнуляет байт, только если он равен `owner`.
   Освобождение ровно в одной точке на путь: после последней verified-записи / последнего чтения,
   **до** ожидания TX, если ответ уже полностью собран в собственном буфере задания и не зависит
   от Flash. Иначе — после отправки. Для каждого задания точка освобождения записывается в отчёт
   с обоснованием (что именно независимо).
3. **Разрешение доступа:**
   * запись/стирание: только у владельца;
   * чтение: разрешено, если байт свободен, **или** владелец не выставил бит «чтение запрещено»
     (как сейчас `table_runtime_blocks_reads`, `sj_runtime_blocked`);
   * незавершённая транзакция секторного журнала (`sj_runtime_blocked`, восстановление) остаётся
     отдельным условием: она запрещает чтение таблиц, пока не восстановлена.
4. Четыре функции готовности заменяются проверкой байта плюс их **особыми** условиями
   (`store_usb_session`, `store[18]`, `store[19]==9`, `mem_storage_ready`, `store_runtime`,
   `cfg[35]`, recovery). Цепочки опроса заданий удаляются, а не обёртываются.
5. Планировщик `user_storage_poll` может диспетчеризовать по байту владельца, но задания без
   Flash-фазы (ответ ждёт TX) по-прежнему опрашиваются: признак A не исчезает.
6. Номера владельцев — константы в одном `.s`-заголовке / `EQU`, C видит их через `#define` только
   для тестов и связующих вызовов.
7. **Никакого универсального фреймворка**: три коротких функции (`flash_claim`, `flash_release`,
   `flash_read_allowed`) и прямое чтение байта.

Обязательные проверки: занятый TX при свободной Flash (второе задание стартует), конкурирующие
задания (захват не проходит), отмена в каждой фазе (байт освобождён ровно один раз, async W25 не
брошен), reconnect / USB reset / reset (старый ответ подавлен, байт свободен после дренажа),
OOM, повреждённый индекс, обрыв питания в каждой фазе.

## 3. Контракт пошагового доступа (задача 2)

1. **Одна операция доступа `acc`**, владелец Flash `ACCESS` на время поиска и сохранения.
   Входной ID **копируется** в операцию при приёме (10 байт + тип источника + контекст ответа
   cmd 8: канал, uniq, источник события, выходы) и принадлежит ей до завершения.
2. **Фазы:** приём → поиск (индекс — ограниченный шаг; fallback — ограниченная порция за проход,
   с сохранением позиции) → проверки (группа, расписание, блокировка, срок, временные ID,
   автодобавление — как сейчас) → сохранение счётчика/первого прохода через async журнал
   (verified) → реле → события журнала → ответ cmd 8.
3. **Не менять:** порядок B25 (реле после verified сохранения, если сохранение нужно; без
   сохранения — сразу, как сейчас), коды ответа cmd 8 (0 / 2 / 1), события и их порядок, правила
   дубликатов, расписаний, счётчиков, первого прохода, защиту от повторного исполнения.
4. **Найденная ячейка и её номер переносятся из поиска в проход** — второй `user_findID` для того
   же ID удаляется.
5. **«Нет данных ещё» ≠ «не найден».** Пока поиск не закончен или Flash занята, результат —
   «ждём», событие 65 «нет в базе» пишется только по законченному полному поиску.
6. **Очередь входов:** новые ID во время операции не теряются и обрабатываются по порядку
   поступления. Размер очереди и что делать при её переполнении — решить по замеру RAM и
   записать (текущее поведение: каждый вход обрабатывается сразу). Повтор того же ключа подряд —
   как сейчас (защиты прежние).
7. **Отмена / сброс / обрыв питания:** сохранение — через существующий секторный журнал
   (атомарность прежняя), незавершённая операция не выдаёт «выполнено», реле не включается без
   verified записи.
8. Все исполняемые изменения — вручную в production `.s` (Thumb-2, Cortex-M3, IAR, AAPCS, CFI).
   C — только объявления, минимальные связующие вызовы и тестовые эталоны.

## 4. Учёт объёма

На каждый коммит: добавлено / заменено / удалено (байт кода по карте IAR, байт RAM),
итоговый BIN и запас RAM. Цель — не больше 92957 и не хуже 160. Если недостижимо без потери
корректности — честный предел с цифрами, цель не объявляется выполненной.

## 5. Измерения

Для каждой затронутой сцены отдельно: максимум инструкций модели за один проход, сумма, число
проходов, стек; Flash, RAM, крупнейший свободный блок heap. Числа — инструкции Unicorn, не время
платы; гарантия 50 мс не заявляется.
