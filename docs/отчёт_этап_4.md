# Этап 4 — канал TCP и адаптер сервера

Доработка: Кряжев А., 2026. Рабочая ветка `codex/comm-core`; изменения оставлены в рабочей копии, без индекса и коммитов.

- `comm_channel` владеет единственным статическим кадром 1040 байт. Производители строят серверные кадры прямо в нём; второй производитель получает обратное давление. Слот освобождается после подтверждения TCP, а не после одного `SEND OK`.
- Передача: `AT+QISEND=0,len` → приглашение `>` (1 с) → тело → `SEND OK` (3 с) → опрос `AT+QISEND=0,0`. Занятость слота или неподтверждённые данные дольше 10 с вызывают переоткрытие TCP.
- Перед каждым новым TCP выполняется явный `QICLOSE` с ожиданием результата. После `ERROR` отсутствие сокета должно быть подтверждено закрытием от модема либо пустым успешным `QISTATE`; иначе канал останавливается с ошибкой. Второе соединение не открывается.
- Регистрация отправляется сразу после открытия TCP прежним производителем, байты сравнены со старым путём. Ответ ожидается 5 с, всего две попытки. После трёх соединений без регистрации — паузы 30/60/120/300 с; три отказа основного адреса переключают на резерв, три резервного — обратно. После 10 минут стабильной связи ступень пауз сбрасывается.
- Статус отправляется каждые 15 с и первым после освобождения занятого слота. Фото, ответы команд и асинхронные ping/DNS его не вытесняют. Внеочередные статусы не продлевают уже начатое ожидание; подтверждение проверяет уникальный номер реально отправленного статуса.
- Три пропуска статуса запускают `QPING` к `ya.ru`: успех требует фактического ответа либо ненулевого числа принятых ответов. При неудаче выполняется DNS с ожиданием 15 с; успешная мета-строка без IP успехом не считается. Есть интернет — событие 13 один раз до восстановления, без сброса модема; нет — TCP заново. Поздний DNS ограждён поколением и 60-секундным окном старого запроса.
- Новый QIRD отдаёт куски прежнему сборщику SLDN; алгоритмы длины, CRC, склейки и обработчики команд сохранены. До успешного финала QIRD и освобождения TX команда не выполняется. Смена TCP отменяет только неподтверждённые серверные пакеты ID/журнала, сохраняя подтверждённые курсоры и состояние USB.
- `user_send_*`, запрос блока прошивки и `photo_send` используют слот под `COMM_NEW_CORE`; без флага сохранён прежний путь. Добавлен изолированный стык `user_comm`. Флаг в Release, `main` и проект IAR не включались: подключение после этапа 6, второго владельца USART3 нет. Этап 5 не начат.

Проверки: все 48 уникальных host-групп, TX `idle/reset/esof/busy/large`, дополнительные профили UART3, SMS debug и `Bootloader/tests/run_tests.py` — **57/57 PASS**. Дополнительно `photo`, `logupload`, `uploadretry` под `COMM_NEW_CORE` — PASS с прежними ожиданиями; в этих группах транспорт слота моделируется, настоящий канал проверяет отдельная `commserver`. UBSan — PASS; восемь контрольных мутаций — **8/8 обнаружены**. Исходники cp1251/CRLF, шапки, отсутствие heap в новых модулях и `git diff --check` — PASS.

Модель канала проверяет регистрацию, статусы, ping/DNS, поздний DNS, закрытие сервером, ошибку закрытия, занятый слот и второй ответ, отсутствие приглашения/результата отправки, неверный ACK, неподтверждённые данные, резерв и паузы без регистрации. Суточный тест: **3374 мусорных блока, 105 переполнений кольца, 106 длинных строк**; обрывы, склейки, бинарные `OK/ERROR/RING/SLDN/NUL`. Вся NOR-модель 2 МиБ совпала с исходной байт в байт, включая области ID, групп, расписаний, настроек и журнала. В этой модели диспетчер допускает только законные ответы регистрации/статуса и тестовый ответ; любой иной вызов команды проваливает тест. Реальные обработчики проверяются отдельными существующими host-группами. После нарушения UART-потока начинается новая изолированная сессия модели; восстановление этапа 5 этим не проверено.

Дополнительные desktop-тесты загрузчика: 8 PASS; три GUI-теста останавливаются до сценариев из-за отсутствующего подходящего `init.tcl` (runtime Tcl 8.6.12, доступные скрипты Git требуют 8.6.18). Загрузчик не изменён. IAR, физическое устройство, COM-порт и настоящий сервер не использовались.

Итого новый путь — **2284 байта static RAM**, +1148 к принятым 1136 байтам этапов 1–3. Контексты этапа 3 теперь 234 байта (предел 250), диагностический снимок 128 сохранён; принятые решения a97b3ae/0140e24 не переделаны. Heap новых модулей — 0; прежний USB-путь сохраняет свои выделения. Пик heap в host-модели фото: **4896 → 4344 из 5120**; это не измерение платы и не доказательство общего пика приложения. Самые крупные локальные кадры SLM около 184 байт, без вложенных libc; запас стека не уменьшался.

По существующей карте High/Size старые RX/GSM/UserGsm занимают не менее 2476 байт RAM: после их удаления кандидат даёт оценочную экономию не менее 192 байт. Пока старое ядро не удалено, эта экономия не реализована. Прирост объектного ARM Flash к этапам 1–3 — 6098 байт, без изменений производителей. Нижняя оценка удаляемого старого кода по IAR — 13645 байт; сравнение её с ARM-объектами не доказывает итоговый лимит +2048. Финальные Flash/RAM, fault_record и границы приложения надо сверить по двум свежим IAR map после подключения; текущую сборку IAR по поручению не запускал.
