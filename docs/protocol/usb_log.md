# USB-журнал монтажника (108/109)

Работает в Release и ReleaseCustomer. Серверный протокол и структура Flash не меняются.

108, только после ПИН: один байт маски (1 AT, 2 GSM, 4 события). Остальные биты игнорируются. Ответ прежний: пустой SLDN 108 с uniqId запроса. Переход от выключенного журнала к включённому обнуляет потери; смена активных категорий сохраняет их до следующей записи. При USB bus reset или отключении кабеля главный цикл снимает маску; конфигуратор после повторного входа передаёт текущий выбор заново.

109: только плата → USB, uniqId=0, байт актуальности=255. Обычный SLDN с общей длиной/CRC16 из `packet_frame`, ядро `crc_asm`. В историческом protocol2.md числа 108/109 в этом месте являются номерами строк таблицы, а не занятыми командами.

## Приоритет и потери

В базе 2ab8aaf кольцо USB TX уже заменено закреплённым источником `work_memory`; USB_TX_RING_BYTES остался в старом заголовке. Журнал не вызывает `work_acquire` или `usb_send`. Кадр 18–63 байта собирается на стеке и под запретом прерываний копируется в очередь `hw_config.c` на 4 кадра (4 × 64 байта ОЗУ). Кадр не длиннее 63 байт всегда идёт коротким пакетом: хост отдаёт его программе сразу, без ожидания следующего пакета. Тело длиннее 45 байт (строка AT до 192) идёт подряд несколькими кадрами по 45 байт с одним временем; у всех, кроме последнего, бит 7. Кадр, не принятый очередью, обрывает строку: хвост не ставится, потеря учитывается, NextConfig выводит начатую строку с пометкой о потере.

EP1 берёт кадр из очереди только когда источник ответа пуст: после подтверждения пакета хостом `Handle_USBAsynchXfer` сначала продолжает ответ, и лишь затем отдаёт журнал. Ответ ждёт не больше одного пакета журнала. Если EP1 свободна, кадр уходит сразу из `USB_Log_Try`. Сброс шины (`USB_Tx_Reset`) очищает очередь прежней сессии. Проверен ответ 1039 байт (верхняя допустимая граница транспорта). 106 — 523 байта; выгрузка событий — до 1038, ID — 1014; фото — до 534; 112 — 98; 111/113 в DIAG — общий источник до 418 байт.

Нет ожиданий USB. При полной очереди, отключённом программном USB или не CONFIGURED счётчик растёт. Следующая принятая запись содержит потери и обнуляет счётчик. Выключенная категория не создаёт запись и не считается потерей. При смене сессии счётчик сбрасывается вместе с маской. При насыщении число означает не менее 65535.

Плата №1, 14.10.2026, сборка 1791941495, опрос статуса раз в секунду: запуск модема 60 с — 251 запись, потерь 0; обычная работа 60 с — 112 записей, потерь 0; статус 59/59, в работе худший ответ 16 мс (при старте платы 3,2 с и без журнала). Без очереди (один пакет) терялось 11 % и 14 %.

Все точки съёма — главный цикл. SysTick обслуживает только питание/время/UART; USB OUT принимает байты, не пишет журнал. Событие 32 снимается в `log_publish` после write/readback/CRC: общая точка синхронного `log_addEvent` и асинхронного добавления, без повторов при retry. Время кадра — публикация; datetime ячейки — время самого события (до синхронизации оно может быть uptime).

Измерено на ELF: максимальный одиночный usb_log — стек 128 байт, 943 ARM-инструкции. Оценка при 72 МГц и условных 8 тактах/инструкцию — 105 мкс (копия+CRC+очередь+PMA); это оценка, без IRQ и измерения на плате. AT-сроки, порядок переходов и рабочая память не меняются.

NextConfig использует один SldnStream на порт. Весь кусок разбирается до возврата ответа; 109 передаётся в журнал, чужие ответы — прежнему ReceiveBytes. Перед записью команды входящий буфер вычитывается тем же декодером; DiscardInBuffer в NEXT отсутствует. Старый SLGT обмен оставлен прежним; сырой журнал старой v5 в этом окне не используется.
