# USB: диагностика связи, команда 112

Версия полезных данных **5**. Одинаковый формат при DOMOVOI_DIAG=0 и 1, в Release и ReleaseCustomer. Команда разрешена без PIN только по USB; серверный канал не выдаёт диагностику и не включает режим наведения. Каждый USB-запрос продлевает частый фоновый QENG на 60 с, ответ отдаёт текущий снимок. Ответ один, без пакета 113. Старый отладочный формат 112 версии 2 удалён.

Все многобайтные числа — unsigned little-endian. Смещения от начала `SLDN`.

| Байты | Размер | Значение |
|---|---:|---|
| 0–3 | 4 | ASCII `SLDN` |
| 4–5 | 2 | Длина 90 (`5A 00`), включая адрес, UID, команду и полезные данные |
| 6 | 1 | Адрес 0 |
| 7 | 1 | UID из запроса |
| 8 | 1 | Команда 112 (`70`) |
| 9 | 1 | Версия 5 |
| 10 | 1 | Состояние/причина, таблица ниже |
| 11 | 1 | Канал: 0 GSM; 1 зарезервирован для WiFi, сейчас не выдаётся |
| 12 | 1 | CSQ: 0–31; 99 неизвестно |
| 13 | 1 | Тип сети: 0 неизвестно/нет обслуживания, 1 GSM/GPRS/EDGE, 3 3G, 4 LTE |
| 14 | 1 | Последняя законченная проверка ya.ru: 0 не было, 1 ping есть, 2 ответ DNS есть, 3 нет ответа |
| 15–21 | 7 | Код оператора PLMN: 5 или 6 ASCII-цифр MCC+MNC, затем NUL; остаток заполнен нулями; все нули — неизвестно |
| 22–25 | 4 | До следующей попытки перезапуска модема, мс; вне ожидания 0 |
| 26–29 | 4 | Питание, мс |
| 30–33 | 4 | Настройка модема, мс |

Полный ответ — **98 байт**. Запрос — обычный кадр длиной 11 байт: `SLDN`, длина `03 00`, адрес, UID, `70`, CRC16 по пяти байтам длины/адреса/UID/команды.

## Код и подсказка монтажнику

| Код | Значение | Одна фраза для экрана |
|---:|---|---|
| 0 | Подключение ещё выполняется | «Идёт подключение — дождитесь завершения этапов.» |
| 1 | Нет доступной SIM, в том числе PIN/PUK | «SIM недоступна — проверьте установку карты и снимите блокировку PIN/PUK.» |
| 2 | Нет сети | «Нет сети — проверьте антенну и покрытие оператора.» |
| 3 | Нет интернета/PDP или завершились безуспешно ping и DNS | «Нет интернета — проверьте APN, баланс и доступность передачи данных у оператора.» |
| 4 | Сервер недоступен/TCP либо перестал отвечать | «Сервер недоступен — проверьте адрес, порт и прохождение трафика до сервера.» |
| 5 | Сервер не принял IMEI | «Сервер не принял IMEI — проверьте регистрацию контроллера на сервере.» |
| 6 | Ожидание перезапуска модема | «Ожидается перезапуск модема — дождитесь окончания отсчёта, причину смотрите в истории сбоев.» |
| 7 | На связи | «Связь установлена — дополнительных действий не требуется.» |

Приоритет: ожидание восстановления → выполняющийся запуск → причина SIM/сети/PDP из состояния модема → результат серверной регистрации/проверки → состояние сервера. TIMEOUT на этапе сети означает код 2, TIMEOUT на этапе PDP — код 3. Ошибка питания/настройки до постановки восстановления в ожидание даёт 0, подробная причина находится в истории. Код 5 сохраняется до успешной регистрации либо нового запуска модема. Код 3 по проверке сервера устанавливается только после отказа **обоих** тестов; промежуточный отказ ping этого кода не устанавливает. Код 7 означает принятую регистрацию до обнаружения серверным надзором потери ответов. Самостоятельного автомата диагностики нет.

Время каждого этапа считается от начала до успеха или остановки, в полных миллисекундах uint32; незапущенный этап — 0, выполняющийся — текущая длительность. Снимок обновляет обычный цикл модема; USB его только читает. При новом запуске модема шесть времён очищаются; мягкий запуск пропускает питание. Новая попытка TCP обновляет только TCP, сохраняя этапы запуска модема. Чтение данных TCP не продлевает уже закончившееся подключение. Ноль сам по себе не различает пропущенный этап и выполнение короче 1 мс.

CSQ, технология и PLMN берутся из существующих фоновых CSQ/QNWINFO; новых AT-команд нет. Пока модем не готов, выдаются 99, 0 и пустая строка. Текстового имени оператора нет: NextConfig может показать PLMN или использовать свой справочник, сохраняя ведущие нули. Проверка ya.ru не запускается по USB: это результат существующего серверного надзора. Отрицательный ping может быть заменён успешным DNS; результат сохраняется между переподключениями/перезапусками модема до следующей законченной проверки, после перезагрузки контроллера равен 0. Успешный DNS не доказывает доступность сервера.

## Кольцо сбоев

Каждая запись `uint32 word`: этап `word & 7`, причина `(word >> 3) & 31`, секунды `word >> 8`. Этапы: 0 питание, 1 настройка, 2 SIM, 3 сеть, 4 PDP, 5 TCP. Секунды отсчитываются **от начала соответствующей попытки запуска модема**, а не от календарного времени; счёт начинается заново при перезапуске модема. Вычитание миллисекунд работает через переполнение uint32. Интервал ограничен одним оборотом миллисекундного счётчика (около 49,7 суток); штатный суточный перезапуск короче этого интервала.

| Причина | Значение |
|---:|---|
| 0 | Нет ошибки; в действительные записи не заносится |
| 1 | Таймаут на указанном этапе |
| 2 | AT ERROR |
| 3 | Неподходящий ответ модема |
| 4 | SIM не установлена |
| 5 | SIM требует PIN |
| 6 | SIM требует PUK |
| 7 | Нет регистрации в сети |
| 8 | Не поднят/потерян PDP |
| 9 | Ошибка TCP |
| 10 | Потеря границ потока ответа модема |
| 11 | Модем не отвечает |
| 12 | Неподдерживаемый тип модема |
| 13 | Сервер отказал в регистрации IMEI |
| 14 | Сервер не ответил на регистрацию либо надзор обнаружил потерю ответов |
| 15 | Ping и DNS не подтвердили доступ в интернет |

Кольцо переживает перезапуск модема, очищается при перезагрузке контроллера; чтение не очищает его. Плановый разрыв TCP во время звонка не записывается как сбой. Переполнение вытесняет самую старую запись. Повторные реальные отказы записываются отдельно. Причины 1–3 и 10–12 показываются вместе с этапом, без UART-счётчиков или полей автоматов.

## Отладочная диагностика

Только DOMOVOI_DIAG=1: команда 111 версии 6 содержит прежние 58 uint32 и добавленные индексы 58 errors, 59 overflow, 60 ORE, 61 FE, 62 NE, 63 состояние канала, 64 состояние сервера, 65 состояние восстановления, 66 остаток ожидания. После неё приходит пакет профилирования 113 прежнего формата с тем же UID. Внутренние времена 30 AT-шагов, маска их завершения, modem last_code/APN и UART-регистры остаются только в отладочной части; в ответе 112 их нет. Общие времена шести этапов и кольцо существуют в единственном экземпляре.

## LTE-метрики и совместимость

Смещения 0–93 сохранены. NextConfig принимает v3 (93 байта, длина 85, CRC в 91–92), v4 (96 байт, длина 88, CRC в 94–95) и v5. Для v3, не-LTE и неизвестного RSRP остаётся CSQ. При известном RSRP в v4/v5 LTE показываются RSRP/RSRQ. Оценка RSRP: > −90 хорошо, −100…−90 средне, < −100 плохо; RSRQ: > −10 хорошо, −15…−10 средне, < −15 плохо. SINR на экране скрыт; стендовый link_diag.py выводит «SINR сырой N».

Режим наведения: только USB 112 продлевает срок на 60 с (один uint32-таймстамп). QENG ставится в каждом новом интервале 2 с через прежний comm_channel_query; номер интервала хранится одним байтом, его оборот 512 с длиннее срока. Фоновый запрос выполняется после серверных данных, звонков и SMS; занятый канал может задержать замер. Полный цикл шести команд остаётся раз в 30 с. Без новых запросов через 60 с быстрый опрос гаснет. Диапазон и полоса публикуются только вместе с полным QENG; сброс и отказы очищают их в 255, как RSRP.

Полный фоновый цикл с AT+QENG="servingcell" остаётся раз в 30 с через comm_channel_query. Common V2.24 §9.25 не задаёт отдельный таймаут; используется COMM_T_AT_SIMPLE (300 мс). Поля отсчитываются после "LTE", остальные поля могут содержать кавычки и hex. Не-LTE, отсутствие полного ответа, ERROR/таймаут и неготовность модема очищают метрики, диапазон и полосу в 255. Новых задач и буферов опроса нет.

2026-10-13, плата №1, проба probe/qeng-raw: RSRP/RSRQ у SLM336 приходят индексами CESQ. Прошивка принимает RSRP 0–97, RSRQ 0–34 и переводит в прежние единицы 112: RSRP = 141 − индекс (модуль дБм), RSRQ = (40 − индекс) / 2 (модуль дБ, целочисленно вниз). Числа с минусом, как у Quectel, уже выражены в дБм/дБ: сохраняется их модуль. RSSI приходит со знаком; srxlev и конец строки проверяются до публикации.

Реальные ответы `48,21,-67,54,27` и `41,19,-70,61,20` дают RSRP/RSRQ/SINR `93/9/54` и `100/10/61`. Оба завершились OK; одна строка 90 байт укладывается в 300 мс. SINR хранится сырым: масштаб не подтверждён, формула `/5 − 20` не применяется. Серверный байт «Сигнал», CSQ, регистрация, QNWINFO и событие 38 сохраняют прежний контракт; формат 112 v4 не меняется. Исправленная прошивка на плате не проверялась.
