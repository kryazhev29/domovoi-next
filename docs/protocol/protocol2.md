1. Контроллер имеет 5 структур хранения данных, каждая ограничена по количеству записей и имеет сквозную нумерацию ячеек для их хранения:
- ID абонентов - 50000 ячеек 50000 записей
- Группы - 64 ячейки 64 записи
- Расписания - 64 ячейки 64 записи
- Настройки - 1 ячейка
- Праздники - 1 ячейка

Разработчик, применяя параметр Таймштамп, должен обеспечить:
1. минимизацию трафика при синхронизации. Для этого разработать алгоритм, при котором уже синхронизированные записи, синхронизацию которых подтвердил контроллер ответом на команду 13 от сервера, не будут повторно синхронизирваться в случае обрыва связии или возникновения непредвиденнных проблем в процессе синхронизации.
2. простой алгоритм, позволяющий без лишних флагов и меток, определять какие именно записи синхронизированы, какие нет

Мнение заказчика:
Ввести понятия:
ТШ - таймштамп
ТШ_К - текущий таймштамп всей структуры контроллера, которые тот передает серверу при отправке пакета регистрации
ТШ_БДЗ - таймштамп конкретной записи в БД на сервере
ТШ_СИНХРО - таймштамп начала синхронизации - нажатие кнопки Применить.

п.1. Для каждой ячейки/записи ведется таймштамп ее изменения, по которому система определяет необходимость ее синхронизации с контроллерами. Кнопка ПРИМЕНИТЬ появляется только при изменеии/добавлении/удалении записи и обновления ее таймштампа до ТШ_БДЗ > ТШ_К. При нажатии кнопки Применить, создается ТШ_СИНХРО. Кнопка Применять сразу становится не активной. Этот таймштамп является точкой среза. На синхронизацию пойдут все записи ТШ_БДЗ между ТШ_К и ТШ_СИНХРО. Для контроллеров, которые онлайн синхронизация начинается сразу, для оффлайн по мере их подключения к серверу. ТШ_СИНХРО хранится в БД и выводится в ЛК в виде дататайма последней синхрониазции.
п.2. ТШ_СИНХРО Передается в командах синхроонизации в сторону контроллера. Если ответ от контроллера содержит ТШ_синхро, это означает, что записи, содержащиеся в пакете синхронизированы и их ШТ_БДЗ в базе заменяется на ТШ_синхро.

Важно! Если синхронизация не завершена и/или находится в процессе, при этом админ произвел какие либо изменения, появляется кнопка Применить, при нажатии на которую:
- формируется новый ТШ_СИНХРО+N
- для всех записей в БД, имеющих ТШ_БДЗ = ТШ_СИНХРО (уже синхронизироваанные) производится замена ТШ_СИНХРО на ТШ_СИНХРО+N, что бы повторно их не синхронизировать
- процесс синзронизации по точке среда ТШ_СИНХРО завершается и начинается новый по точке среза ТШ_СИНХРО+N, на синхронизацию пойдут все записи ТШ_БДЗ между ТШ_К и ТШ_СИНХРО+N

Записи ID абонентов являются уникальными и не могут сождержать одинаковые ID. Проверка на дубли производится при добавлении через WEB интерфейс, добавленые по SMS или вторегистрацию.
Эта логика была проработана и заложена для простоты обмена и минимизации мобильного трафика. Является основой при проектировании структуры БД. Может быть изменена.
