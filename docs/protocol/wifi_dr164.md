# Сервер через Wi-Fi-мост USR-DR164 (RS-485)

Написано 19.10.2026 (task/wifi). На плате не проверено.

## Как включается

Мост стоит на общей линии RS-485 (USART1) вместе с камерой. Канал идёт через мост, когда в настройках
режим 485 активный (`rs485Mode = 1`) и в таблице периферии есть запись типа 1 «Wi-Fi модем»
(адрес в записи не используется: у моста адреса нет). Иначе сервер идёт через GSM, как раньше.
GSM-модем работает всегда: звонки и SMS не зависят от моста, звонок канал моста не рвёт.

Мост работает в командном режиме (`AT+TMODE=cmd`), TCP-клиент моста держит соединение с сервером сам.
Адрес берётся из `server1` (хост и порт) и записывается в мост командой `AT+NETP=TCP,CLIENT,порт,хост`
при каждом включении канала. Резервный сервер через мост не используется.

## Обмен

| Действие | Команда мосту | Ответ |
|---|---|---|
| Выключить эхо (начало каждого включения) | `AT+E=off` | `+ok` |
| Адрес сервера | `AT+NETP=TCP,CLIENT,порт,хост` | `+ok` |
| Есть ли TCP (раз в 1 с при включении, раз в 3 с в работе) | `AT+TCPLK` | `+ok=on` / `+ok=off` |
| Точка доступа (только для состояния) | `AT+WSLK` | `+ok=Disconnected` / `+ok=SSID(MAC)` |
| Кадр серверу, куски не длиннее 1000 Б | `AT+SEND=n`, затем n байт | `+ok` до данных |
| Данные сервера, опрос каждые 100 мс при свободном слоте | `AT+RECV=n,0` (n ≤ 512, по месту в приёмнике) | `+ok=k,данные` или `+ok=0` |
| Проверка интернета по запросу надзора | `AT+PING=ya.ru` | `+ok=Success…` |
| Переоткрытие TCP | `AT+TCPDIS=off`, `AT+TCPDIS=on` | `+ok` |

Ответ читается после тишины линии (межбайтовый срок 10 мс, как у камеры); срок ответа 0,8 с, ping 6 с.
Короткие ответы ложатся в буфер 48 Б, данные `AT+RECV` — в общий слот передачи `frame` (слот на это время
производителю не выдаётся). Окна подтверждений нет: после данных `AT+SEND` слот свободен.

Мост из коробки стоит в прозрачном режиме и на `AT+E=off` молчит. Тогда команды идут с префиксом `USR`
(`USRAT+TMODE=cmd`, `USRAT+Z`), после перезапуска моста (8 с) включение повторяется.

## Отказы

Нет ответа или отказ настройки — включение неудачно (`COMM_CH_OPEN_FAILED`), сервер делает обычную
паузу и повтор. Четыре неудачных включения подряд — канал переходит на GSM (`USB-журнал 17/10, значение 1`)
и остаётся на GSM до нового сеанса канала (перезапуск модема, ночной перезапуск, перезагрузка).
Потеря TCP замечается `AT+TCPLK` не позже 3 с; дальше обычное переоткрытие.

## Съёмка на той же линии

Пока камера снимает, мост на паузе: команды ему не идут, текущая операция забыта, TCP мост держит сам.
После съёмки сразу проверяется `AT+TCPLK`. Байты камеры мост видит как мусор; что он на них отвечает —
проверить на стенде (открытый вопрос с 01.10).

## Настройка точки доступа: USB 113

После ПИН (102). Тело `SSID\0ключ\0` (SSID 1–32 байта, ключ до 63, пустой ключ — открытая сеть) —
прошивка пишет в мост `AT+WMODE=STA`, `AT+WSSSID=`, `AT+WSKEY=` и перезапускает его `AT+Z`;
ответ 113 сразу: 0 принято, 1 занято (съёмка, занятый слот, прежняя настройка), 2 неверные данные.
Пустое тело — состояние: байт 0 «канал через мост» (0/1), байт 1 связь: 0 точки доступа нет,
1 точка доступа есть, 2 TCP сервера открыт. Стенд: `Стенд_Domovoi\Скрипты\wifi_setup.py`.
SSID и ключ хранятся только в мосте; в настройках контроллера их нет.

## Не сделано

Возврат с GSM на Wi-Fi без нового сеанса; скорость моста по умолчанию 115200 (должна совпадать
с линией 485); передача данных мосту блокирует главный цикл на время кадра (1000 Б ≈ 90 мс при 115200).
