# Сервер через Wi-Fi-мост USR-DR164 (RS-485)

Переписано 20.10.2026 (task/wifi-sockb): командный режим через сокет B, мост на 460800, камера на той же линии.
На плате не проверено.

История: 19.10 командный режим на сокете A отдавал мусор во всех пакетах после первого за соединение;
в тот же вечер канал переведён в прозрачный режим (проверен на плате, 1792419754), но в прозрачном режиме
камера на одной линии с мостом невозможна. 20.10 на стенде (мост на USB-485, без платы) найдено:

- дефект в прошивке моста V1.0.15, сокет A: каждый новый TCP-сегмент мост пишет в начало одного буфера,
  а читает с накопленного смещения — целым приходит только первый; у сокета B этой ошибки нет
  (200 обменов 1–1000 Б с 00/0A/0D/FF, очередь, частичное чтение — 0 ошибок);
- в командном режиме мост читает линию кусками по 100 Б (или до тишины 20 мс) и на кусок с 0x0D или 0x0A
  отвечает `+ERR=-1` через 1,5–2 мс — посреди пакета камеры; на 115200 это почти каждый пакет фото;
- мост на 460800 при линии 115200 (в 4 раза быстрее) почти не слышит камеру: ответы на 0–2,5 % посылок,
  только после 20 мс тишины, длиной 0,24 мс; в буфер моста из трафика камеры ничего не попадает.

Логи и скрипты стенда: `Стенд_Domovoi\Скрипты\dr164_lab.py`, `dr164_timing.py`, `Логи\2026-10-20_dr164_опыты`.

## Как включается

Мост стоит на линии RS-485 (USART1). Канал идёт через мост, когда в настройках режим 485 активный
(`rs485Mode = 1`) и в таблице периферии есть запись типа 1 «Wi-Fi модем» (адрес не 0: адрес 0 по Протоколу2 резерв).
Иначе сервер идёт через GSM. GSM-модем работает всегда: звонки и SMS не зависят от моста, звонок канал моста не рвёт.
Камера (тип 3) может стоять на той же линии.

Порт переключается: с мостом USART1 работает на 460800, камера во время съёмки — на `rs485_baud()` (115200).
Адрес сервера — `server1` (хост и порт); резервный сервер через мост не используется.

## Поиск и настройка моста

При каждом открытии канала мост ищется по очереди: 460800 без префикса (уже наш), 115200 с префиксом `USR`
(из коробки, прозрачный режим), 115200 без префикса (командный режим прежних прошивок), 460800 с префиксом.
Перед попыткой без префикса уходит одиночный CR: он закрывает мусор в буфере моста (байты камеры, команда на
чужой скорости), иначе следующая команда получит `+ERR`. Проверка — `AT+E=off`.

Мост наш (460800): один раз за включение платы сверяется `AT+SOCKB` с `TCP,порт,хост`; совпало — дальше TCP.
Мост не наш или сокет B смотрит не туда — настройка и перезапуск (пауза 8 с):

| Шаг | Команда | Зачем |
|---|---|---|
| 1 | `AT+E=off` | без эха; проверка, что мост отвечает |
| 2 | `AT+EVENT=off` | уведомления `+EVENT=…` не должны попадать в ответы |
| 3 | `AT+TCPTO=0` | мост не рвёт TCP по тишине |
| 4 | `AT+NETP=TCP,SERVER,15013,10.0.0.1` | сокет A сервером на самом мосте: наружу не подключается, сервер не видит второго соединения с того же адреса |
| 5 | `AT+SOCKB=TCP,порт,хост` | сокет B — клиент сервера 1 |
| 6 | `AT+TMODE=cmd` | командный режим |
| 7 | `AT+UART=460800,8,1,NONE,NFC` | своя скорость моста |
| 8 | `AT+Z` | перезапуск, затем поиск с первой попытки |

Точка доступа по USB 113 вставляет после шага 1 `AT+WMODE=STA`, `AT+WSSSID=`, `AT+WSKEY=`.
Три подряд неответа на `AT+TCPLKB` — при следующем открытии мост сверяется заново.

## Обмен

| Действие | Команда мосту | Ответ |
|---|---|---|
| Есть ли TCP (раз в 1 с при включении, раз в 3 с в работе) | `AT+TCPLKB` | `+ok=on` / `+ok=off` |
| Точка доступа (когда TCP нет) | `AT+WSLK` | `+ok=Disconnected` / `+ok=SSID(MAC)` |
| Кадр серверу, кусками до 1000 Б | `AT+SNDB=n`, пауза 30 мс после `>`, данные | `>`, затем `+ok=n`; `+ok=0` — сокет закрыт, переоткрытие |
| Данные сервера, раз в 50 мс | `AT+RCVB=n,0`, n — место в приёмнике, до 512 | `+ok=k,<k байт>` / `+ok=0` |
| Проверка интернета по запросу надзора | `AT+PING=ya.ru` | `+ok=Success…` |
| Переоткрытие TCP | `AT+TCPDISB=off,0`, `AT+TCPDISB=on,0` | `+ok` |

Ответ разбирается после тишины линии 10 мс. Мост отвечает на команду через ~21 мс (обрабатывает по тишине 20 мс).

## Съёмка

Съёмка забирает линию и порт: операция моста отменяется (недописанный кадр уйдёт заново, прерванная настройка
начнётся снова), данные сервера ждут в мосте. Сборщик кадра камеры пропускает мусор: команда начинается только
с 0xAA, пакет данных ищется по номеру и длине со сдвигом на байт. После съёмки мосту уходит одиночный CR
(закрыть мусор камеры в его буфере), затем `AT+E=off` и проверка TCP.

Остаточный риск: редкий ответ моста через 20 мс тишины может совпасть с началом ответа камеры — пакет не сойдётся
по сумме и будет запрошен повторно.
