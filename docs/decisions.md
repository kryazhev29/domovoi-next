# Решения владельца

Перед изменением поведения свериться с этим файлом. Дата 07.10 фиксирует действующее решение по `cleanup_findings.md` и отчётам `history/`.

- 2026-10-12 — Фотофиксация (Алексей): команда 7 только для теста камеры; штатно один снимок после включения хотя бы одного выхода прохода любым источником, первая периферия 485 типа 3 (JPEG/C328) при rs485Mode=1. Используется photo_start с прежними ограничениями команды 7, включая FW (бит 11); отказ молчаливый, реле не ждут фото. Разблокировка и реле useInBlock не снимают, тип 2 (Interceptor) исключён до согласования протокола. Съёмка, очередь, событие 129 после записи, бит 13 и команда 21 сохраняются.

- 2026-10-07 — Только плата v5 HW139, STM32F103CB и SLM336; старые платы не поддерживаются.
- 2026-10-07 — Один проект: гибрид C + ASM-ядра под замер реальных операций; проекты C и полного ASM удалены, порог пользы ядра 5%.
- 2026-10-07 — Зеркало настроек 0x1CD400 убрано; сохранение атомарно в A/B.
- 2026-10-07 — Обработчики пультов 433 и RFID-485 убраны.
- 2026-10-07 — Измерение VCC убрано; два внешних входа сохраняются.
- 2026-10-07 — Расписания одним пакетом: ячейки 16 Б + хвост 16 Б; неприсланные ячейки стираются.
- 2026-10-06 — Звонок: снять трубку и положить примерно через 1 с; быстро восстановить подключение после отбоя.
- 2026-10-07 — ПИН 4–5 цифр: в настройках число 0–99999 (uint32 младшим байтом вперёд), заводской 4321; старый ASCII переводится при чтении. SMS и USB 102 принимают также универсальный ПИН по формуле заказчика только для IMEI из 15 цифр. [Реализация и проверки](history/PIN_20261007.md).
- 2026-10-07 — Перенос старого журнала убран; старый формат не мигрирует.
- 2026-10-07 — CRC базы ID только в ОЗУ.
- 2026-10-07 — Тяжёлый тест на физической плате отложен; эмулятор его не заменяет.
- 2026-10-07 — Загрузчик работает через сервер и через USB.
- 2026-10-07 — APN: заводское поле «Оператор» пустое; ручной → сеть (CGCONTRDP) → MNC → пустой, отказ QIACT включает резерв без миграции старого `internet,gdata,gdata`, удачный источник сохраняется до перезапуска питания модема.
- 2026-10-07 — Разблокировка: сцены оцениваются раз в минуту по часам контроллера и сразу после старта, команд 5/12/14/23 и принятой регистрации; без времени сервера действует только ручная.
- 2026-10-07 — Разблокировка: при двух реле useInBlock открывающего реле нет; без реле useInBlock выходы не переключаются, но команды привода всё равно игнорируются.
- 2026-10-07 — Разблокировка: журнал использует только существующие события начала/конца, новые номера не вводятся.
- 2026-10-07 — Разблокировка: выполненное состояние не сохраняется во флеш; после старта оно выводится из сохранённых триггеров, настроек и часов.
- 2026-10-07 — Разблокировка: щелчок управления → конец серии импульсов (для уровня — 1 с) → разрыв ИК; при снятии сначала замкнуть ИК, затем вернуть уровень в состояние до разблокировки.
- 2026-10-07 — Событие 40: аргумент 1 — RCC->CSR [31:24], если есть IWDGRSTF/WWDGRSTF/SFTRSTF/LPWRRSTF; PVD пишет только 39, POR/PIN сами по себе не пишутся. SFTRSTF пишется и при уже записанной причине программного сброса. При отказе журнала флаги и PVD-метка остаются до следующего старта; после приёма в очередь флаги снимаются, повторов в текущем запуске нет.
- 2026-10-11 — USB 112 v3 доступна при DIAG=0/1: шесть этапов в мс, код причины, GSM/сигнал/PLMN/сеть, ya.ru и кольцо 10 сбоев; внутренние счётчики остаются DIAG, серверный протокол не меняется; формат — docs/protocol/usb_link_diag.md.
- 2026-10-12 — D13: SMS #setout включает выход общим исполнителем команды 8, с onCmdServer, useInBlock, разблокировкой, паузой и режимом из настроек; без дополнительного события управления.
- 2026-10-12 — D09: при захвате ID команда 6 исключает обычный доступ по Wiegand; выбранный считыватель выдаёт только ответ 8 и событие 78, после ID или таймаута доступ возобновляется; звонки и серверные команды сохраняются.
- 2026-10-12 — D31: значение cnt=255 означает конечные 255 повторов; бесконечного импульсного режима нет, уровень и разблокировка используют прежние настройки.
- 2026-10-12 — Звонок: проверка номера → открытие → ATA → ~1 с → AT+CHUP. ATH на SLM336 возвращает OK, но не завершает ни снятый, ни неотвеченный вызов (проверено на плате №1 12.10); CHUP выбран по MeiG Common V2.24 §7.4. Отбой подтверждается пустым AT+CLCC (§7.6), одного OK от CHUP недостаточно; повторы CHUP ограничены 2,5 с от ATA/начала отклонения. После аварийного отбоя данные отпускаются, повторный доступ ждёт пустого CLCC. Во время загрузки FW (бит 11) — CHUP без ATA, проверки доступа и записи прохода; команда 8 не исполняется, карты работают. При возврате данных срок TCP ACK обновляется: голосовая пауза не закрывает исправный сокет. [Проверки и AT-лог](history/SLM336_HANGUP_20261012.md).
- 2026-10-12 — Праздники в расписаниях: 0 и неизвестные значения onHoliday трактуются как 1 (игнорировать праздники); 2 — только в праздники, 3 — кроме праздников. Дни недели и время проверяются во всех режимах.
- 2026-10-12 — Восстановление SLM336: паузы 10/30/60 мин проходят с включённым модемом и обслуживанием звонков/SMS; питание снимается только на короткий разряд перед включением. URC CREG/CGREG/CEREG 1/5 отменяет паузу без снятия питания; активный звонок откладывает перезапуск до отбоя. Только первый POR/PDR без флагов программного/WDT/LPWR сброса пропускает разряд; PWRKEY 2 с и загрузка 2 с сохраняются без аппаратного документа MeiG. [Логика, время и память](comm-core-design.md).
