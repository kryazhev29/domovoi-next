# Этап 1 — порт UART модема, 02.10.2026

Реализация и проверки готовы в `codex/comm-core`. Этап 2 не начат.

- `Modules/comm_uart.*`: RX-кольцо 512 (511 полезных), один производитель IRQ / потребитель main; peek/consume без копирования и переноса хвоста. Переполнение отбрасывает новый байт; ORE/FE/NE отбрасывают повреждённый байт, выставляют флаги и насыщаемые счётчики. `errors()` снимает флаги, сохраняя счётчики.
- TX: один принадлежащий UART слот 1040, acquire/commit/release; чужие указатели не принимаются. TXE выдаёт по байту, успех только после TC; ноль завершается без записи DR. Abort отменяет слот/очередь, очищает RX, сохраняет диагностику и не сообщает успех TX. Уже загруженные DR/сдвиговый регистр байты физически отозвать нельзя.
- v5 (`DOMOVOI_APP_HW=139`, без `BOARD_IP_V3`): PB14 AF RTS, PB13 вход CTS, RTSE/CTSE. Проверены `board.h:106–110`, `board.c:33–36`, старый `uart_init`: PB10/PB11, 115200. IP_v3 и MINI — без управления потоком.
- Изоляция: файл требует `COMM_UART_STANDALONE`, отдельно от `uart_stm32f10x.c`; обе реализации экспортируют USART3_IRQHandler и вместе не линкуются. IAR-проект, main, старые UART/GSM и питание не изменены. Для текущего приложения новый модуль не подключён; старый путь сохраняется. Сборка отдельного ARM-объекта — `Tests/build_comm_uart.py`, host-группа — `Tests/run_host.py work commuart <v5|ipv3|mini|mini-ipv3>`.
- Исходники порта и C-тест: cp1251/CRLF, русские комментарии, шапка «Доработка: Кряжев А., 2026»; запись/правки выполнены скриптами. Heap, дополнительного RX/TX-буфера и отладочного вывода нет. TX-слот 1040 из Q1 уже учтён здесь: при дальнейшем подключении второй такой слот не добавлять.

Вопрос архитектору: нужна ли отдельная программная остановка модема по заполнению кольца поверх аппаратного RTS? У STM32F1 RTS следует готовности регистра приёма, **не свободному месту программного кольца** ([ST RM0008, hardware flow control](https://community.st.com/ysqtg83639/attachments/ysqtg83639/stm32-mcu-products-forum/80598/1/13902_STM32_ReferenceManual_11.pdf)). При обслуживаемом IRQ и задержке main кольцо всё равно переполняется; 511 байт при 115200/10 покрывают 44,36 мс. Сейчас защита — явная диагностика потери, а не обещание автоматического торможения на границе кольца.

## Доработка

- TX UART заменён на `comm_uart_tx(data, count)`: указатель без копирования, внутренний массив 1040 и acquire/commit/release удалены.
- Статические буферы принадлежат AT (128) и каналу (1040); живут неизменными до TC/abort/init. Будущие владельцы здесь не реализованы; стек/heap запрещены контрактом, тестовые отправки проверяют владельца.
- На v5 PB14 — GPIO push-pull RTS, PB13 — аппаратный CTS; RTSE выключен. IP_v3/MINI остаются без этих линий.
- Стоп при свободных <128 (384 занятых из 511 полезных), возобновление при занятых <128; обновление после RX/consume/abort. Consume и RTS защищены одной короткой секцией PRIMASK.
- Полярность PB14: LOW разрешает приём, HIGH останавливает модем; соответствует старому RTSG_LOW и [RM0008 §27.3.14](https://www.st.com/resource/en/reference_manual/rm0008-stm32f103xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf).
- SLM336 Common AT V2.24 §2.22, PDF стр. 38–39: AT+IFC=2,2 включает оба направления, уровни сигнала там не описаны; команду выполнит драйвер этапа 3.
- Тесты: команда перед готовым кадром, владение/занятость/NULL/0/1040/1041/TC/abort, пороги/обёртка RTS, поток с 127 байтами в пути без потерь, IRQ при consume/TX. Исходный RTS падает; мутации 6/6 обнаружены.
- Все 43 прежние non-TX host-группы, SMS debug, TX idle/reset/esof/busy/large 5/5, UART v5/ipv3/mini/mini-ipv3 4/4 — PASS.
- Bootloader core/USB/manual/tool — PASS; desktop transport 8/8 — PASS. GUI: 3 ошибки Tcl (init.tcl), до выполнения сценариев; загрузчик/GUI не менялись.
- ARM-модуль: 4 профиля, -Oz/-Wall/-Wextra/-Werror и запрет второго владельца — PASS. RAM 540 = RX 512 + поля 28 (было 1576, −1036); heap 0; Flash объекта 1340 = код 1268 + секции 72 (было 1268, +72).
