# Автоматический APN — исследование 07.10.2026

Уточнение 14.10.2026 (`task/fast-start`): CIMI читается после готовности SIM во время
поиска сети; ручной и известный GSM APN задаются до ожидания регистрации.
CGCONTRDP опрашивается только после EPS-регистрации CEREG (LTE); в GSM сетевого
PDP ещё нет, поэтому резерв сразу использует уже прочитанный IMSI/MNC, затем
пустой APN. Приоритеты и блокировка удачного источника прежние. При мягком
перезапуске удачный IMSI/APN не перечитывается; при отказе всех источников сетевой
APN запрашивается заново. После отключения питания первый QIDEACT пропускается,
после неудачного QIACT очистка контекста перед следующим источником сохраняется.

До изменения кода, база `79422c1`; плата и сервер не используются.

## Возможности и пределы

Локальные руководства из `СофтЭксперт/Для новой системы/документация на GSM модемы/AT команды для модуля MEIG336`:

- `MEIG_SLM3XX_Common_AT Commands Manual_V2.24.pdf`, §12.21, печатные стр. 369–371: `AT+CGCONTRDP=1` читает динамические параметры **активного** контекста, ответ `+CGCONTRDP: <cid>,<bearer_id>,<apn>,…`. §12.2, стр. 312–316: CGDCONT описывает настройки контекста; чтение не доказывает, что APN выдала сеть. §6.12, стр. 119–121: CRSM даёт доступ к файлам SIM.
- `MEIG-SLM3XX_AT Command Manual_EX_V1.08.pdf`, §8.1.1–8.1.3, стр. 82–85: QICSGP задаёт APN/учётные данные, QIACT активирует контекст, QIDEACT деактивирует. Используемые команды подтверждены руководством MEIG, а не только аналогией с Quectel.
- [3GPP TS 27.007, §10.1.23](https://www.etsi.org/deliver/etsi_ts/127000_127099/127007/16.05.00_60/ts_127007v160500p.pdf): динамические параметры появляются при установленном контексте. В LTE default bearer может дать сетевой APN уже после attach; опрос нужен после регистрации и **до** QICSGP/QIDEACT. В GSM/UMTS регистрация/attach без PDP-контекста APN не даёт: пустой ответ/ERROR — нормальный переход к резерву. SLM336 по [спецификации MEIG](https://en.meigsmart.com/userfiles/files/2024/03/11/2024031115551248.pdf) поддерживает GSM/LTE; 3G здесь рассматривается как общее ограничение метода.
- [3GPP TS 31.102, §5.3.14](https://www.etsi.org/deliver/etsi_ts/131100_131199/131102/07.11.00_60/ts_131102v071100p.pdf): EF_ACL — необязательный список разрешённых APN, а не обязательный профиль с APN/логином/паролем. Утверждение «почти всегда пуст» нельзя количественно подтвердить этими документами; полагаться на наличие полезного профиля нельзя. CRSM/EF_ACL в реализацию не нужен.

## Вывод до кода

Порядок: **ручной (если задан) → CGCONTRDP=1 → таблица MNC → пустой APN**. Непустой сетевой APN используется без ручных учётных данных; MNC также без них. Пустой/ERROR CGCONTRDP или неизвестный MNC пропускаются. Отказ QIACT переводит к следующему источнику; повреждение потока остаётся обычным восстановлением связи. Таймауты прежние: простой AT 300 мс, QIDEACT 40 с, QIACT 150 с; новых повторов и автомата нет. Уточнение реализации: после таймаута QIACT резерв ждёт восстановления границ AT; неудачная ресинхронизация завершает попытку обычным отказом.

После первого успешного QIACT источник и нужные данные сохраняются до перезапуска питания модема; при переподключении используется тот же источник, без повторного перебора. Ручной успешный APN исключает опрос автоматики; после его отказа CGCONTRDP может уже не найти default bearer, поэтому таблица и пустой APN обязательны. Заводское поле из 32 нулей запускает автоматический путь; сохранённый старый ручной APN не мигрируется, но получает резерв при отказе.

Выбор default APN сетью при отсутствии APN от UE подтверждён [3GPP TS 23.401, §5.3.2.1](https://www.etsi.org/deliver/etsi_ts/123400_123499/123401/16.11.00_60/ts_123401v161100p.pdf); это APN из подписки HSS, а не обязательный файл SIM.

Метод документирован и пригоден для минимальной резервной цепочки, но не гарантирует обнаружение любого M2M APN: default bearer может отсутствовать, быть другим CID или IMS, оператор может требовать явный частный APN/аутентификацию. Тогда заказчик задаёт APN,логин,пароль вручную. APN платы №1 и фактическая поддержка конкретной прошивки SLM336 здесь не подтверждались.

## Реализовано

Один новый шаг таблицы — CGCONTRDP; новый автомат не вводился. Разбор принимает CID 1, APN в кавычках/без них до 100 байт, проверяет допустимость строки для AT. Хвост динамических IPv6-параметров за 192 байтами строки отбрасывается, как существующий длинный USSD: APN находится в начале ответа. Перебор прекращается после успешного QIACT и возобновляется только после нового питания модема.

Если все источники отказали и удачного ещё нет, обычный мягкий перезапуск начинает цепочку заново. Заводское поле остаётся нулевым после общего обнуления `config`; лишней записи APN нет.

USB-диагностика связи Release, существующая команда 112: версия `v[0] = 2`, в `v[3]` биты 24–31 — источник (`0` ручной, `1` сеть, `2` MNC, `3` пустой). Добавился шаг SLM_NET_APN, поэтому номера следующих шагов и длина массива времён увеличены на один. В ReleaseCustomer эта диагностика по-прежнему отключена.
