КАМЕРА COM — прямой опрос C328 / OV528 с компьютера

Запуск: Камера_COM.exe. Python устанавливать не требуется.
Из исходников: python camera_com_gui.py или двойной щелчок Камера_COM.pyw.
Для предпросмотра из исходников нужен Pillow; в EXE он включён.

1. Подключите USB–UART к компьютеру, выберите его COM-порт и скорость камеры.
   Обычно начинают с 115200; доступны также 57600, 38400, 19200 и 9600.
   Программа сама не перебирает порты и не меняет скорость камеры.
2. TX адаптера → RX камеры; RX адаптера → TX камеры; GND → GND.
   Адаптер на фотографии имеет TTL-выводы с маркировкой 3,3 В.
   Питание камеры и допустимые уровни сигналов определяйте по её паспорту:
   наличие вывода VCC 3,3 В не означает, что он подходит для питания камеры.
   Переходник RS232 или RS485 нельзя подключать к TTL-выводам напрямую.
3. «Проверить связь» выполняет только SYNC/ACK, без снимка.
   «Снимок» получает один JPEG и освобождает COM-порт.
   «Начать опрос» повторяет снимки; пауза отсчитывается после сохранения фото.
   «Стоп» прерывает обмен/ожидание, закрывает COM-порт. При ошибке цикл останавливается.
4. Снимки и журнал camera_com.log сохраняются в выбранной папке.
   По умолчанию у EXE это Фото_камеры_COM рядом с программой.
   Журнал содержит TX/RX в HEX; ротация — 3 МБ, три предыдущих файла.
   Имена JPEG содержат порт, дату и время. Незавершённые снимки не сохраняются.
5. «Демо (без COM)» использует существующий эмулятор C328 и тестовый JPEG.
   Для проверки адаптера выберите реальный COM-порт вручную.

Алгоритм перенесён из User/photo.c:
  SYNC       AA 0D 00 00 00 00   — ждём ACK и SYNC, в любом порядке
  ACK SYNC   AA 0E 0D 00 00 00
  INITIAL    AA 01 00 07 00 07   — JPEG 640×480
  PACK SIZE  AA 06 08 40 00 00   — 64 байта целиком / 58 данных
  SNAPSHOT   AA 05 00 00 00 00
  GET JPEG   AA 04 01 00 00 00   — длина в ответе AA 0A 01 LL MM HH
  PACKET     AA 0E 00 00 LL HH   — номер пакета начиная с нуля
  FINISH     AA 0E 00 00 F0 F0
Проверяются номер, длина, сумма байтов по модулю 256 и нулевой завершающий байт.
SYNC: 30 запросов с шагом 50 мс. Прочие стадии: до 3 запросов с ожиданием 2 с.
Между управляющими командами выдерживается минимум 50 мс; между пакетами — нет.
Общий срок съёмки 60 с; размер JPEG не более 65535 байт, как у МК.
Дополнительно на ПК проверяются границы JPEG и декодирование (если есть Pillow).
Адрес камеры не задаётся: в самом протоколе C328 нет адреса устройства.
Инверсия UART из экспериментальной ветки МК не переносится на USB–TTL:
обычный USB–UART передаёт стандартный 8N1, DTR/RTS и управление потоком отключены.

Проверки без оборудования:
  python -m unittest discover -s Tools/Photo -p test_camera_com.py -v
Сборка EXE из каталога Tools/Photo:
  powershell -ExecutionPolicy Bypass -File build_camera_com.ps1
Результат: Tools/Photo/build/dist/Камера_COM.exe

Проверка на эмуляторе не подтверждает распиновку адаптера или связь с реальной камерой.

Ошибка 31 при открытии CH340 (проверено на COM7, 30.09.2026):
Драйвер 4.0.2026.2 отклонял SetCommState и у программы, и у pySerial.
Установка подписанного 3.7.2022.1 устранила ошибку без перезагрузки.
Архив взят по ссылке из официальной инструкции Arduino:
https://support.arduino.cc/hc/en-us/articles/13148652511260-avrdude-ser-open-can-t-set-com-state-for-COMn
Резервная копия прежнего драйвера и журнал установки находятся на стенде:
Камера_COM/Драйвер_CH340/backup_4.0.2026.2 и repair.log.
Скрипт repair_ch340_driver.ps1 требует администратора, заранее распакованного
драйвера, единственного подключённого CH340 и действительной подписи каталога.
Windows также меняет сохранённые экземпляры того же USB hardware ID.
Скрипт не перезагружает компьютер и не отключает проверку подписей.
Версию после установки проверяем через Get-PnpDeviceProperty:
Win32_PnPSignedDriver может некоторое время показывать прежнюю версию.
